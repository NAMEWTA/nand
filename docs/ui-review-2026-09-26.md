# NAND UI 与模块切换验证

本次对应 #15、#16 和 #9 剩余的占位页设计。#14 Iconic 移植不在本轮范围。

## 改动

- 模块状态应用串行执行。终端状态未改变时，不激活、停用或重开终端 leaf；队列失败后仍可继续处理后续请求。
- 评论状态使用独立的“已解决 / Resolved”文案。引用支持键盘跳转，删除保留在原生更多菜单中。
- 模块关闭页及未开放功能采用统一空状态；不添加新业务能力。
- 设置导航使用原生按钮；Agent 的 CLI 路径、权限、参数分别呈现，下载来源和下载操作分行。
- 统一评论、设置、用量窗口、看板控件和配置弹窗的间距、层级、焦点与窄屏样式。保留现有 13 套看板主题和自定义配色。
- 没有改变视图类型、命令 id、设置字段、评论存储或最低 Obsidian 版本。未引入新依赖。

设计参考：[Linear 的层级与弱边框](https://linear.app/now/behind-the-latest-design-refresh)、[Notion 的评论组织](https://www.notion.com/help/comments-mentions-and-reminders)、[Warp 的终端主题设置](https://docs.warp.dev/terminal/appearance/themes)。

## 验证结果

### 自动化

- `pnpm run build`：通过，已重建 `main.js`。
- `pnpm run lint`：0 个错误、197 个既有警告，没有增加。
- `test:settings-nav`：18 项通过，包含 6 项新增模块生命周期测试，以及 Agent 表单写回原字段的断言。
- `test:editor-comments`：通过，包括中英文状态、更多菜单删除及既有锚点、存储、高亮检查。
- `test:terminal-agent`：178 项通过。
- `test:theme-studio-colors`、`test:card-move`、`test:refresh-scope`、`test:scroll-root`：通过。

### 真实宿主

- 分别保留 3、2、1 个终端，各连续切换看板、编辑器 10 轮：view、terminal instance 与 PTY session id 均保持不变。
- 智能体关闭再开启后，3 个终端均完成初始化；超过 40 秒后仍存在，逐个激活后执行 echo 均成功。
- 上述复测未捕获到未处理异常；无 GPU 环境使用既有渲染器回退。
- 280、320、400px 侧栏无评论横向溢出；长连续字符串和多行回复正确保存及换行。
- 中文显示“已解决”，英文显示“Resolved”。引用跳转选中了预期原文，键盘焦点可见。
- 编辑器 leaf 移到弹出窗口后仍显示两条评论，更多菜单出现在该弹出窗口中，无未捕获异常。
- 原始测试笔记逐字节保持不变。
- 13 套看板主题均切换到正确的 `data-theme`，每套均保留测试库的 9 张卡片。
- 窄版 Agent 设置无输入框越界；旧设置 fallback 的首页、编辑器、终端及同步页面均直接调用验证通过。

## 验证边界

- 使用真实 Linux Obsidian 1.13.7。未在 Windows、macOS、手机真机或 Obsidian 1.8.7 中执行；fallback 检查是在 1.13.7 中直接调用旧渲染路径。
- 窄设置截图通过限制实际设置容器宽度获得，不等同于移动端真机验证。
- 用量截图验证排版，不验证供应商网络接口、认证或额度查询。
- 未复现 issue #15 中只出现一次的异常刷屏；本轮也不将短时间复测当作长期内存稳定性的证明。
- 测试库使用仓库内 Linux 终端二进制并启用离线模式。准备阶段遇到既有绝对路径归一化问题，因此测试进程工作目录设为 `/`，未改动产品路径逻辑。
- 不发布版本，不关闭 GitHub issue。
