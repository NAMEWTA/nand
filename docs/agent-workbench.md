# 智能体工作台

工作台的 **AI Agent** 页把终端、编程智能体的原生会话历史和用量放在一起。它可以运行普通 Shell，以及这些 CLI 智能体：Claude Code、Codex、Gemini CLI、OpenCode、Pi（`@mariozechner/pi-coding-agent`）和 Grok（`xai-org/grok-build`）。仅桌面端可用。请先在本机安装各 CLI。默认情况下，从 NAND 启动的 CLI 和普通终端使用本机已有的登录（“系统账号”），与你在系统终端里直接运行时一致，不需要重新登录；NAND 不会替你安装或登录。需要把登录隔离在当前库时，可另建“托管账号”。

六个智能体默认都已启用。可以在 **设置 → 智能体** 中分别关闭，并设置程序路径。

## 会话与布局

主区域的「+」菜单同时创建终端、智能体和浏览器标签。空输入按 Enter 新建终端；输入 `claude` 可选择 Claude Code，`example.com` 打开网页，`localhost:3000` 使用 HTTP，`obsidian 插件` 使用浏览器设置中的搜索引擎。方向键选择、Enter 确认、Esc 取消；输入法组字期间不会启动。

拖动标签可排序或移入其他组，拖到四边可分屏，拖回可合并；最多四个标签组，每个终端标签最多四个窗格。分隔线可调比例，中键关闭标签，运行中的终端关闭需确认。进程退出后可“重新启动”。浏览器与终端可并排，详见[浏览器](browser.md)。

侧栏列出会话、历史、智能体看板和用量统计。Ctrl/Cmd+J 打开跳转面板，可搜索近期标签、最近关闭和历史，或新建标签；部分操作有菜单中的快捷键提示。四列智能体看板按“需要处理、运行、已完成、空闲”组织，空闲默认隐藏；可搜索、筛选、快速发送并点击返回标签。

工作中显示转圈，完成显示对勾；后台完成产生铃铛未读，激活标签后清除；等待权限显示橙色问号并进入“需要处理”。状态来自原生 Hook；没有可靠事件就显示未知，输出安静不代表完成。

关闭工作台叶子只释放显示界面，存活会话可重新接回。关闭终端标签、停用智能体或卸载插件会结束相应进程。Obsidian 重启后恢复标签组和布局，不自动重放命令；普通终端显示“重新启动”，带有效原生标识的智能体显示“恢复会话”。恢复使用原账号、目录和 CLI 恢复参数，校验失败不会改为新会话。

- 终端菜单提供复制、粘贴、查找、提示符导航、清屏、回滚、字号、目录、重命名、结束及附加材料。
- 网址普通点击可弹出操作菜单；Ctrl/Cmd 点击使用默认目标，Shift+Ctrl/Cmd 反向。默认目标在浏览器设置中选择。
- 库内 `路径:行:列` 引用在 Obsidian 定位；拖入文件插入路径，拖入文本按粘贴处理。
- 粘贴会剔除 ESC 等控制字符并在应用要求时使用括号粘贴；有选区时 Ctrl/Cmd+C 复制，否则中断。IME 仅发送最终提交文本。Shift+Enter、kitty 与 Windows win32-input-mode 按终端协议处理。

## 快捷命令

标签条的快捷命令按钮支持添加、分组、复制、编辑和再次运行。终端命令在新 Shell 标签执行；智能体命令在新交互会话输入就绪后提交提示词。终端右键的插入入口只把命令放进当前输入区。看板的“快捷命令”小组件可以列出并运行这些已保存的终端快捷命令（智能体模块的公开接口 `agent.quick-commands` 只提供名称、类型、范围和运行，命令内容不外传）。旧版启动预设不迁移为快捷命令，需重新配置。

## 启动智能体

新会话默认在库目录中启动（“在库目录中启动”）。“确认提示”默认是 **YOLO**：第一次启动带有此类参数的智能体时，NAND 会询问“让智能体跳过确认？”，并说明智能体可以不经询问修改库里的文件。在 **设置 → 智能体** 中选择 **Manual** 可保留 CLI 自己的确认提示。

| CLI | 程序 | YOLO 添加的参数 |
|---|---|---|
| Claude Code | `claude` | `--dangerously-skip-permissions` |
| Codex | `codex` | `--dangerously-bypass-approvals-and-sandbox` |
| Gemini CLI | `gemini` | 无 |
| OpenCode | `opencode` | 无 |
| Pi | `pi` | 无 |
| Grok | `grok` | `--permission-mode bypassPermissions` |

找不到程序时，NAND 会提示并给出安装链接；特殊位置可在 **设置 → 智能体** 中填写程序路径。六种 CLI 都可以填写账号名称，支持中文与标点；名称以 NFC/trim 规范化后使用完整 SHA-256 作为内部标识，显示名称保留。

- **系统账号（默认，名称留空）**：不改动 HOME、XDG 和各 CLI 的目录变量，也不清除已导出的 API 密钥，CLI 读写它自己的配置目录（`CLAUDE_CONFIG_DIR` 或 `~/.claude`、`CODEX_HOME` 或 `~/.codex`、`GROK_HOME` 或 `~/.grok`、`GEMINI_CLI_HOME` 或用户主目录下的 `.gemini` 等）；Claude Code 不设置 `CLAUDE_CONFIG_DIR`，这样 macOS 钥匙串中的登录条目不变。设置 → 账号里的默认项会显示实际路径。
- **托管账号（名称非空）**：HOME、配置、数据、缓存和临时目录位于 `.nand/agents/<device-id>/accounts/<provider>/<stable-id>/`，不继承宿主的登录或 API 密钥，登录与系统账号互不影响。“添加账号”新建托管账号，之后在该账号里用 CLI 自己的方式登录；NAND 不会把系统登录复制进托管账号。非空非法名称会报错。

升级时，若旧版本留下的库内默认账号目录含登录或会话历史，它会作为托管账号“库内账号（旧）”保留，不移动、不删除任何文件；此后的默认值是系统账号。从桌面图标启动 Obsidian 时，NAND 会用 `$SHELL -ilc` 恢复 PATH 和 shell 配置里导出的 CLI 目录变量（有超时；Windows 跳过）。

旧插件账号目录和 helper 必须完成一次 Obsidian 主进程冷重启后才迁移。旧有损目录名可能碰撞时，需明确选择旧目录或新建身份，不猜测归属。来源先复制/校验再切换，恢复副本保留在库内；重启不会把活跃凭据退回复制阶段。登录状态跨设备不保证可移植，允许重新认证。

## 原生历史

“本库”和“全部”只是显示筛选：“本库”按工作目录的真实路径筛选；“全部”不限工作目录，包括库外目录的记录。无论当前选哪个账号，NAND 都会扫描系统账号（你本机 CLI 自己的会话目录，见下表的真实路径）以及已登记的托管账号（当前库 `.nand/agents/` 下的目录），并把标题、提示词文本和工作目录等写进库内的可重建索引 `.nand/terminal-agent/<device>/index.sqlite`；该索引因此包含库外会话的内容，随 `.nand/` 一起备份或同步。来源必须是 CLI 的会话日志（系统账号限定在各 CLI 的会话目录内，登录和设置文件不会被当作会话），不接受符号链接或失效来源。恢复仍要求工作目录在当前库内。

历史使用虚拟列表，可搜索模型、首条提示词与预览，按智能体筛选、创建/更新时间排序、智能体/目录分组，隐藏空记录；展开查看详情，收藏、归档、改标题、复制恢复命令、导出或在新标签恢复，也可拖入标签组。需要最新记录时点刷新。原生记录不存在或校验失败时报告错误，不用新会话顶替。

| CLI | 读取位置 |
|---|---|
| Claude Code | 账号的 `CLAUDE_CONFIG_DIR`（系统账号默认 `~/.claude`）中 `projects` 下的 JSONL |
| Codex | 账号的 `CODEX_HOME`（系统账号默认 `~/.codex`）中 `sessions` 下的 JSONL |
| Gemini CLI | `.gemini/tmp/*/chats` 中的 JSON 和 JSONL（账号的 `GEMINI_CLI_HOME`，系统账号默认用户主目录）；工作目录来自记录、`.project_root` 或 `projects.json` |
| OpenCode | 只读打开 `opencode.db`；读取根会话及其消息和文本部分 |
| Pi | 账号的 `PI_CODING_AGENT_DIR`（系统账号默认 `~/.pi/agent`）中 `sessions` 下的 JSONL |
| Grok | 账号的 `GROK_HOME/sessions`（系统账号默认 `~/.grok`）中的 `session.json` 与 `chat_history.jsonl` |

NAND 自己的标题、标签、收藏和归档状态保存在 `.nand/terminal-agent/<device>/history.json`，不会修改 CLI 的日志。同目录的 `index.sqlite` 是可重建的索引。导出写入 `.nand/content/NAND Exports/` 文件夹并自动打开；重名时加编号后缀，不覆盖已有文件。

## 额度与用量

订阅额度是提供方返回的账户状态，与 token 用量分开显示。Obsidian 底部状态栏的用量项在任何页面都可见，点击打开的面板按提供方显示窗口或模型、已用/剩余比例、重置时间和检查时间，可切换账号。新会话使用新账号，已运行会话保持原身份。用量统计页按日期和智能体展示已知 token、会话数与图表。刷新失败时保留最近一次有效结果并标记为过期。Gemini 保留每个模型各自的额度。没有额度接口的提供方不显示剩余比例，也不会编造。在 **设置 → 常规 → Obsidian 状态栏** 中选择显示已用或剩余、详细或精简模式，并可隐藏用量项；右键任一 NAND 状态栏项目也能调整。

token 来自原生日志。输入包含缓存读写，缓存数字是输入中的明细。Codex 取会话累计值，Claude 对同一消息的重复用量去重。费用只显示 CLI 原生记录的值。汇总缺少某些会话时标注“仅统计已知用量的会话”，任何会话缺少费用时，汇总费用显示“费用未知”。自动化使用运行前后原生累计值的差额。

## 上下文材料

在智能体会话的右键菜单中选择“附加笔记或档案…”。选中的笔记（已打开的笔记使用编辑器中的内容）会在智能体输入就绪后，作为一次括号粘贴放进输入区，不追加回车。[浏览器](browser.md)采集的文本、元素和截图通过同一接口附加。会话已结束，或输入区在 10 秒内没有就绪时，NAND 会报告错误。

## 看板技能按钮

看板有两套独立的技能按钮：

- **常用操作条**：点击操作条的齿轮，在“技能”列表中配置；按钮保存在当前看板 Markdown 的 `skills` 字段。
- **技能小组件**：在 **设置 → 看板 → 小组件** 中开启，再点小组件内的齿轮配置；按钮保存在全局设置的 `home.skillWidgetButtons`，由各看板共用。

两处均可添加、删除和排序按钮，配置图标、名称、智能体、手填的技能名称、提示词模板、新会话工作目录及“直接发送”。保存后生效，取消配置不写入。新建按钮默认先预览，技能名称留空时发送普通提示词。技能发现与技能库的使用见[看板](dashboard.md#更多分区)。

以下显式调用语法已于 2026 年 10 月 10 日核对官方文档：

| 智能体 | 提示词中的技能名称 | 参考 |
|---|---|---|
| Claude Code | `/name`，支持 `/plugin:skill` | [Skills](https://code.claude.com/docs/en/skills) |
| Codex | `$name` | [Build skills](https://learn.chatgpt.com/docs/build-skills) |
| Grok | `/name`，支持带限定前缀的名称 | [Skills guide](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/08-skills.md) |
| Pi | `/skill:name` | [Skills guide](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/skills.md) |
| OpenCode | 普通提示词；文档中的 skill 工具由模型选择 | [Agent skills](https://opencode.ai/docs/skills/) |
| Gemini CLI | 普通提示词；`/skills` 管理技能，由模型激活技能 | [Agent skills](https://geminicli.com/docs/cli/skills/) |

OpenCode 和 Gemini CLI 的按钮须将技能名称留空，通过普通提示词表达意图。NAND 不会为模型选择的技能工具猜测用户命令。填写技能名称不代表 CLI 已加载该技能；实际运行仍依赖 CLI 的配置和权限。

模板支持 `{{path}}`、`{{title}}`、`{{folder}}`、`{{stage}}`、`{{paths}}` 和 `{{input}}`。值只替换一次，值里的花括号和未知变量原样保留。两处的 `{{title}}` 都是按钮名称，`{{stage}}` 为空；上下文在点击时取值：

| 入口 | 模板上下文与文件引用 |
|---|---|
| 常用操作条 | `{{input}}` 是完整闪念草稿；`{{path}}` 是已配置的闪念目标路径，`{{folder}}` 是其父目录，`{{paths}}` 及文件引用包含该目标。未配置目标时，这三个路径变量及文件引用为空。运行技能不创建笔记，也不清空草稿。 |
| 技能小组件 | 只提供按钮名称；输入、路径、目录和文件引用为空。调用来源单独记录当前看板路径，不把它填入路径变量。 |

预览只提供最终提示词文本框，确认后按编辑后的原文派发，取消则不发送。“直接发送”仅作用于该按钮，使用点击时生成的提示词。当前配置的新会话使用所选智能体已有的账号和权限设置；智能体模块关闭或交付失败时显示错误，不会自动开启模块。

自动化运行记录保存最终提示词、文件引用、来源和终端标识；启动前先保存调用记录，相同调用 ID 不重复执行。“已启动”只表示交付，完成状态由 CLI 原生生命周期报告。10 秒交付超时只结束等待，已接受任务请查看运行记录。关闭页面会取消其等待中的交付，已由运行时接受的任务遵循现有自动化生命周期。

## 状态 hook

为了知道智能体是在工作、等待还是空闲，NAND 在启动 Claude Code、Codex、Gemini、Grok、Pi 或 OpenCode 会话（交互式或由自动化启动）时，会在所用账号的 CLI 配置中安装一个小型状态 Hook（系统账号写入你真实的 CLI 配置，托管账号写入库内）：

| CLI | NAND 写入的文件 |
|---|---|
| Claude Code | Claude 配置目录中的 `settings.json`（合并） |
| Codex | `CODEX_HOME` 中的 `hooks.json`（合并） |
| Gemini CLI | 账号 HOME 下的 `.gemini/settings.json`（合并） |
| Grok | `GROK_HOME` 中的 `hooks/nand-status.json` |
| Pi | Pi 智能体目录中的 `extensions/nand-status.ts` |
| OpenCode | 账号的 `OPENCODE_CONFIG_DIR` 中的 `plugins/nand-status.mjs` |

安装保留用户设置和其他 Hook。托管账号的配置在库内，先原子认领实际原文件，再以无覆盖发布写入；并发或中断版本留在配置文件旁的 `.nand-install` / `.nand-backup-<id>` 恢复目录（可能含你的原配置）。脚本位于账号的 `runtime/nand-automation-hook.cjs`，每个终端的事件目录也在库内；在设置里关闭“状态 Hook”会移除托管账号的 Hook。

系统账号（默认）写入你真实的 CLI 配置，设计与 Orca 相同：

- **一份全局脚本、所有库共用**：`~/.nand/agent-hooks/`（`nand-hook.sh`、`nand-hook.cjs`，Windows 为 `nand-hook.cmd`）。脚本随版本原子更新；只有在 NAND 启动的终端里（会话环境里有 `NAND_HOOK_DIR`、`NAND_HOOK_TOKEN`、`NAND_HOOK_NODE`）才把事件转发给对应的库，否则立即吞掉输入退出，不做任何事。
- **配置里每个事件只有一条固定条目**，内容与库无关、所有库完全相同：脚本存在、可读且可执行才运行，否则吞掉输入后成功退出（`if [ -f … ] && [ -r … ] && [ -x … ]; then /bin/sh … 事件; else …; fi`）。所以安装是幂等的，条目已齐全时不写文件。
- **不按库安装或卸载**：关闭库、停用模块、关闭“状态 Hook”开关都不会移除它们。只有在 **设置 → 智能体** 里点“移除系统状态 Hook”才会移除：按完整命令串精确匹配，只删 NAND 的那一条，同组的其他命令、matcher 和其他字段原样保留；之后脚本目录也会清理。
- **写入方式**：读取 → 只增删 NAND 那一条 → 在同目录写临时文件 `.<文件名>.nand-tmp-*` → 重新核对文件未变后 `rename` 原子替换（文件已被别处改过则从新内容重来）。文件临时占用时短暂等待并重新读取，最多尝试三次；持续失败时保留原文件并报告错误。写前把原文件备份到 `~/.nand/agent-hooks/` 下的 `backups` 目录（每个文件保留最近 5 份，可能含你的原配置），不在你的配置目录旁留文件。
- **脚本目录同样受保护**：`~/.nand` 或 `agent-hooks` 是符号链接、解析后不在用户主目录内、脚本本身是链接时，安装、chmod 和移除都拒绝并提示，不会跟随链接改动或删除别处的文件。
- **拒绝而不强写**：目标是符号链接、解析后越出用户主目录、JSON 解析失败（含空文件、只有空白的文件、不是对象）时不写入，并提示涉及的文件；交互会话照常启动，自动化会报错。
- **Pi / OpenCode**：写 NAND 专属文件 `extensions/nand-status.ts`、`plugins/nand-status.mjs`，内容固定、与库无关。文件不存在才创建；存在时只有内容与 NAND 当前版本一致，或与 NAND 上次写入的摘要一致（未被改动的旧版本）才会覆盖或在移除时删除，否则视为你的文件，原样保留并提示。
- 自动化任务无论“状态 Hook”开关如何都会为运行确保这些条目存在。

没有本终端令牌时 Hook 不执行事件写入；它不联网、不记录提示词。Pi 等待真正空闲，OpenCode 忽略子会话和可恢复错误。

各 CLI 的目录信任、登录和 hook 权限仍由 CLI 自己管理。Codex 要求通过 `/hooks` 命令审查新增或变更的 hook，NAND 不会跳过这一步，详见 [Codex hook 文档](https://learn.chatgpt.com/docs/hooks)。

其他 NAND 模块发起的提示词任务默认最多运行十分钟。等待登录、目录信任或权限时，任务可以显示所属终端；取消或超时会结束该任务的进程。任务完成后通常关闭终端；调用方可以明确保留终端供查看，并负责后续关闭。其他手动打开的终端不受影响。

提示词结果来自 CLI 的原生完成事件和完整答案。Claude Code 与 Codex 的 hook 提供最后一条回答，Gemini 提供 `prompt_response`，Pi 提供本轮结束后的 assistant 消息，OpenCode 通过本地会话接口提供当前轮已完成的文本部分。没有答案、进程退出却没有答案，或答案超过 2 MiB UTF-8 文本时，任务明确失败；过大的 hook 输入也会产生明确错误。hook 事件暂存中不保存提示词或工具输入。任务沿用所选 CLI 的现有账户与权限设置，可用的用量来自原生记录。

## 终端组件

终端由一个小型原生程序 `nand-pty` 运行（MIT，源码在 `native/pty-server`）。插件只通过它的标准输入输出通信，不监听端口，也不需要令牌。启动时 NAND 核对协议版本（3），版本不符时明确失败。插件停止时，它会结束全部终端。在 Windows 上使用 ConPTY，并通过作业对象保证子进程随之退出。

组件为 Windows x64、macOS x64/arm64、Linux x64/arm64 发布，始终由 CI 构建。首次使用从插件同版本 Release 下载 `nand-pty-<平台>-<架构>`（Windows 加 `.exe`）与正式摘要，保存到 `.nand/helpers/<device-id>/<platform-arch>/<version>/`。各版本独立，升级保留旧文件。摘要缺失或不匹配时停止并保留来源。

已有匹配字节可在正式摘要核验后复用，旧明文回执不能赋予执行信任。本机受保护回执允许已验证文件离线复用；异机无法解密、证明失效或宿主保护不可用时需要重新联网核验。Linux `basic_text` 不作为可信保护，不能承诺离线可用。开发 `NAND_PTY_BINARY` 只复制到库内执行，不直接在库外运行。

下载错误会说明失败原因。HTTP 404 表示此版本尚未发布当前平台的组件或校验文件；其他 HTTP 错误显示状态码和插件版本，连接失败与超时分别提示。开发者控制台记录原始 Release 资产地址，不记录重定向签名或认证信息。失败后保留已安装的二进制，可以重新尝试。

## 使用限制

请先在本机安装并登录各 CLI，并完成它自己的目录信任和权限提示。Obsidian 退出后，终端和自动化任务不会继续运行。不同 CLI 提供的历史、完成事件和额度信息不同，缺失的信息显示为未知或不可用。Windows 上已在真实 Obsidian 验证组件安装、Shell 输入与尺寸调整、提示词任务的进程清理。提示词测试使用原生 hook 协议测试程序；Claude/Codex 真实模型运行的完整答案、其他 CLI 适配器，以及 Windows/macOS 的完整账号流程仍待人工验收。Linux Obsidian 1.13.7 的本地 PTY/Hook 测试不等于真实服务商登录或模型执行验收。
