# 数据保存、备份与恢复

用户资料优先保存为 Markdown；必要的 NAND 配置与运行数据集中在当前库的 `.nand/`，不以插件安装目录保存业务资料。

| 数据 | 保存位置 |
|---|---|
| 看板 | 用户选择的看板 Markdown |
| 个人与企业档案、附件 | 所选档案目录，默认“档案/个人档案/”与“档案/企业档案/” |
| 独立操作 | `NAND/自动化/<名称>-<短 ID>/操作.md` |
| 习惯、记账、阅读、番茄记录 | NAND/ 下各领域目录 |
| 全局设置 | `.nand/config/settings.json` |
| 设备终端设置 | `.nand/config/devices/<device-id>.json` |
| 图标与备份 | `.nand/icons/` |
| 评论与锚点 | `.nand/editor/comments/` |
| 自动化运行、通知回执 | `.nand/automation/<device-id>/`、`.nand/notifications/<device-id>/` |
| 终端索引与历史标注 | `.nand/terminal-agent/<device-id>/` |
| 浏览历史与站点授权 | `.nand/browser/<device-id>/` |
| 故障草稿、缓存 | `.nand/recovery/`、`.nand/cache/` |

CLI 原生日志、认证及 Chromium Cookie 由对应宿主管理，不复制进 Vault。设备身份保存在 Obsidian 本机存储中；复制库不能代替设备归属设置或 CLI 登录。连接令牌仅在运行时使用。

## 日常备份

1. 完成编辑器与面板中的保存，确认没有未保存或冲突状态。
2. 备份用户 Markdown、相关附件和整个 `.nand/`。备份工具需包含隐藏目录。
3. 恢复前关闭相关模块，保留当前故障文件副本，再恢复确认有效的资料与配置。
4. 重新开启后检查内容和设备设置；不要为了恢复运行而自动重放中断的外部操作。

缓存和索引可以重建，实体正文、业务记录、评论和通知回执不能按缓存清理。浏览器 Cookie、CLI 账号与日志需要按各宿主方式独立备份。

## 保存失败和冲突

读取失败、损坏文件或无法解析的受管区域会阻止写入。JSON 保存保留上一有效快照；图标使用其独立备份轮换规则。磁盘错误不会被显示为保存成功。

遇到错误先保留当前输入，检查权限、同步冲突与文件内容。支持重试的记录面板提供错误详情和重试；恢复草稿位于 `.nand/recovery/drafts/`。档案冲突可复制草稿，再重新载入原始资料；草稿 JSON 不是可直接导入的 Markdown。

不同字段或记录的并发修改可合并，同一字段冲突需要人工处理。原始笔记未保存时先保存编辑器，不绕过保护写入。删除后的实体文件可能保留 nand-deleted 标记，这是逻辑删除，不是待恢复的正常记录。

## 当前格式

当前实现不扫描、迁移或双写旧存储格式，也不自动删除旧文件。已有旧数据应先独立备份，再按当前界面和文档核对；不能将旧插件 data.json 当成新存储入口。

语言切换只影响界面，不改文件路径、身份标识、笔记正文或动作参数。
