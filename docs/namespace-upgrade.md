# NAND 数据命名空间升级

本次修复 #17–#22（不含 #14）会改变视图类型、评论目录、界面状态键、CSS 类名和终端上下文标识。旧安装必须先运行单独提供的 `nand-namespace-migrator` 工具；插件不会在启动时自行搬移数据。已有 `data.json` 缺少 `dataNamespaceVersion: 1` 时，仅显示升级说明并阻止设置写入。全新安装正常初始化。

## 升级顺序

1. 备份整个库和 Obsidian 配置，并保留上一版插件的 `main.js`、`styles.css`、`manifest.json`。
2. 在上一版 Obsidian 的当前库中，按工具包 README 执行 `local-state.cjs` 的 `prepare`。它先导出当前库的界面状态，再准备新键；已有新值优先。每个库、每个设备分别处理。
3. 完全退出 Obsidian。运行文件迁移预检，检查输出路径及警告；有冲突或损坏文件时先解决，不能靠手动添加版本号绕过。
4. 执行迁移，指定库外的全新备份目录。工具保留笔记内容与评论 JSON 原始字节，转换桌面、移动端及已保存布局中的视图类型，并迁移受管的终端上下文技能。版本标记最后写入。
5. 安装本次构建的三个插件文件，启动 Obsidian。检查评论、固定标签页、日历筛选和背景设置；随后执行工具的 `finish` 清理该库旧界面键。
6. 网页和音乐页面需要重新登录。插件使用新的 Electron 会话名，迁移工具不复制、合并或删除原会话目录。

自定义配置目录通过工具的 `--config-dir` 参数指定。移动设备先关闭应用，在可运行 Node.js 的电脑上处理完整库副本，再同步数据和插件；设备本地界面偏好若无法导出，只能在升级后重新设置。第三方 CSS 片段需要用户适配当前类名。

## 中断与回滚

迁移中断时保持 Obsidian 关闭，用原备份目录执行 `--resume`，不要创建第二份不完整备份。回滚前同样退出应用，执行 `--rollback`，恢复上一版插件，然后在该库恢复本地界面状态。回滚会先在备份目录保存升级后的文件和整个新评论目录；升级后新增评论不会自动合并进旧格式，需从这份恢复副本中人工核对。

文件迁移预检不会扫描历史上误写到进程工作目录的文件。确认库中正确文件及备份后，再人工清理误写副本；不要将不同库或时间不同的上下文文件自动合并。

## 当前持久化约定

- 评论：`.nand/editor/comments/`，不改写 Markdown 笔记。
- 视图：`nand-dashboard-view`、`nand-editor-view`、`terminal-view`。
- 界面状态：`nand.dashboard.*`，通过 Obsidian 的库级存储读写。
- 终端上下文：`NAND_CONTEXT_PATH`、`.agents/skills/nand-obsidian-context/`。
- 外部工具保留迁移映射，主仓库不保留旧运行时别名；版权来源声明保持原文。
