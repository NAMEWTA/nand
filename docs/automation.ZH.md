# 自动化与通知

自动化和通知是工作台里的两个页面。图标栏的 **自动化** 图标打开管理页，侧栏有“任务”和“运行记录”。图标栏底部的 **通知** 铃铛打开收件箱（有未读时显示数字），侧栏可在“未读”和“全部”之间切换。底部状态显示正在运行的自动化和需要处理的事项。关闭自动化后，仍可查看历史和通知。

## 操作类型

| 操作 | 作用 | 手动 | 定时 | 需要桌面端 |
|---|---|---|---|---|
| 提醒 | 发送一条带你所写内容的通知 | 是 | 是 | 否 |
| 新建待办 | 在已注册看板的某张卡片中添加待办 | 是 | 是 | 否 |
| 运行智能体 | 在库内的工作目录中用提示词启动编程智能体 | 是 | 是 | 是 |
| 终端脚本 | 在工作目录中运行 PowerShell 或 Bash 脚本 | 是 | 是 | 是 |
| Obsidian 命令 | 运行一个 Obsidian 命令 | 是 | 否 | 否 |
| 打开笔记 | 打开一篇笔记 | 是 | 否 | 否 |
| 打开网页 | 在[内置浏览器](browser.ZH.md)中打开网页（浏览器模块关闭时用系统浏览器） | 是 | 否 | 否 |
| 浏览器流程 | 在明确选择的页面和账号上执行已验证的有限步骤 | 是 | 是，仍受页面状态和确认要求限制 | 是 |

Obsidian 命令的结果只表示命令已被调用。脚本的结果取真实退出码。

## 创建自动化

新建和编辑都在自动化页中进行，不使用对话框。可以使用页面上的“新建自动化”、命令“新建自动化”，或下面几种入口，它们会打开自动化页并带上来源和标题。保存或取消后回到任务列表。

- **待办提醒**：看板待办分区中任务上的铃铛按钮，以该任务为来源打开编辑器。提醒仍属于看板笔记里的这条任务；任务勾选完成或被删除后不再调度。
- **档案提醒**：在档案记录的菜单中选择“新建自动化”。自动化列表里的“来源”会打开这条档案。
- **自动创建待办**：选择动作“新建待办”，选择目标看板和卡片，再输入待办内容。可以马上创建，也可以按周期创建。
- **独立操作**：在自动化页新建，例如“运行智能体”或“终端脚本”，运行方式可选“快捷操作（手动）”“指定时间”“重复执行”或“马上执行”。

在任务列表里，每条自动化都可以立即运行、暂停或恢复、编辑和删除。

待办目标必须是能显示和管理待办的卡片，包括混合分区中的任务卡。备忘、普通项目、数据库查询和网页卡等不是有效目标。目标改名不会改变它的身份；目标被删除、类型改变或不再唯一时，请重新选择有效的卡片后再保存。写入前 NAND 会重新检查磁盘上的目标，不会自动改投第一张卡片，也不会转换卡片类型；同一次运行有运行 ID，重复确认不会插入两次。

要把操作作为看板按钮使用：保存时把运行方式设为“快捷操作（手动）”，选择“添加到看板”并选择目标看板，见[看板](dashboard.ZH.md#快捷操作)。

## 运行方式与时间

- Obsidian 必须运行。没有云端调度、操作系统守护进程、远程运行，也不会创建 worktree。
- 可选“马上执行”“指定时间”，以及“重复执行”：预设为“每小时”“每天”“工作日”“每周”，或“自定义”（五字段 Cron 表达式或 RRULE）。RRULE 支持 `FREQ=HOURLY`、`FREQ=DAILY` 和 `FREQ=WEEKLY`，配合 `BYHOUR`、`BYMINUTE`，每周还支持 `BYDAY`。其他字段会在保存时被拒绝，不会被默默忽略。
- 日历计划明确保存时区，默认使用本机时区。因夏令时而不存在的本地时间会被跳过，重复的一小时按两个不同的时刻处理。NAND 每分钟检查一次计划，窗口获得焦点时再检查一次。
- 只考虑最近一次错过的时间，不补排所有错过的执行。默认宽限 720 分钟（可在“补执行宽限”中修改），另加两分钟的轮询容差。超出宽限，或上一次运行尚未结束时，该次记为 **已跳过**。
- NAND 先保存待执行记录和调度游标，再执行动作。重启后，未完成的运行被标为 **已中断**，不会自动重放。每次运行都有运行 ID，所以待办不会重复插入。
- 每个定义保留最近 100 条已结束的运行；进行中的运行始终保留。“清理已结束的历史”只移除已结束的运行，保留进行中的运行和投递回执。
- 倒计时和纪念日的提醒在小组件的设置里配置，通过同一个自动化服务运行，日期由小组件决定。无需保持看板打开。

## 通知

通知渠道按每条自动化分别设置，不是全局默认值。

| 渠道 | 行为 |
|---|---|
| 应用内 | 写入收件箱，并显示一条 Obsidian 提示 |
| 系统 | 桌面操作系统通知，需要系统的通知权限 |

“执行后通知”可选“成功或失败时”“仅失败时”或“不通知”。

在收件箱里可以全部标为已读、清理已读通知，以及打开通知的来源。清理后仍保留防止重复投递的回执。回执显示“已提交”“待投递”“失败”或“状态未知”：重启后无法确认投递结果的渠道保持“状态未知”，不会自动重发。通知按运行 ID 去重。

通知是独立的功能模块。在 **设置 → 常规 → 功能模块** 中关闭后，自动化照常运行，结果只显示一条 Obsidian 提示，不写入收件箱；重新开启后，之前的通知仍在。

## 运行记录

| 状态 | 含义 |
|---|---|
| 待执行 | 等待开始 |
| 执行中 | 操作正在运行 |
| 已提交；完成状态未知 | 操作已启动，但还不知道它是否完成 |
| 已完成、失败 | 操作的结果 |
| 已停止 | 你停止了这次运行 |
| 已中断 | 运行时 Obsidian 被关闭 |
| 已跳过 | 超出宽限窗口，或上一次运行仍在进行 |

可以按动作和状态、按智能体筛选列表。删除定义会保留它产生的运行记录，仍可查看其历史；请先停止进行中的运行。

## 智能体操作

可以选择任何已启用且已安装的智能体，见[智能体工作台](agent-workbench.ZH.md)。会话方式有：

- **每次新建**
- **沿用上次存活会话**：上次的会话仍然存活且空闲时沿用，否则新建
- **指定会话**：从历史中选择（可搜索），或填写准确的原生会话标识；Pi 还需要会话文件路径。NAND 用 CLI 自己的恢复参数恢复该会话，不会回退到新会话；会话不可用时这次运行失败。

手动运行会自动打开终端；定时运行可在运行记录中点“打开”。终端菜单的“收起面板”保留进程；关闭工作台标签只隐藏界面，重新打开可接回存活的进程。结束会话，或在运行记录中点“停止”，才会结束进程。关闭自动化页不会停止调度。

Claude Code、Codex、Gemini、Grok、Pi 和 OpenCode 通过 NAND 在启动会话时安装的原生 hook 报告生命周期。已有的 hook 和设置会保留，原文件会备份，见[智能体工作台](agent-workbench.ZH.md#状态-hook)。对没有原生完成事件的 CLI，运行一直显示“已提交；完成状态未知”，直到进程退出或你停止它；输出变安静从不被当作成功。需要输入提示词的 CLI 必须发出可识别的输入就绪信号，否则运行超时失败，并提示手动完成初始化。

各 CLI 的目录信任、登录和 hook 权限由 CLI 自己管理，请先手动完成。如果“确认提示”是默认的 YOLO，且该智能体带有此类参数，请先手动启动一次该智能体并确认权限模式；在此之前，自动化运行会失败，并提示“请先手动启动一次该智能体，确认已配置的权限模式”。用量取原生会话累计值在运行前后的差额；取不到基线或原生记录时显示缺失，不推算费用。

## 浏览器流程

执行动作选择**浏览器流程**，选择已验证的版本，填写公开变量，并为每个页面范围明确绑定页面。定义保留该版本及页面和账号选择。版本或页面缺失时显示不可用，不会改用当前活动标签页。必填秘密只能通过浏览器流程中经过核对的手动运行提供，不能保存在自动化定义里。

手动与计划运行使用同一套自动化历史、取消和**打开流程结果**操作；浏览器用同一运行 ID 记录各步检查。调度要求浏览器和自动化模块保持启用，选定的原生页面已在指定账号及范围内加载。计划运行不会显示页面、跳过登录或绕过最终提交确认；条件不满足时明确失败或中断，等待人工处理。

关闭浏览器会撤销其正在运行的流程，并使新触发不可用，不会自动重新开启模块。关闭自动化会取消其拥有的流程。定义和历史结果保留在磁盘。重启中断未完成的运行，不重放页面动作。验证、暂停恢复、秘密和保存位置见[浏览器流程](browser.ZH.md#可复用浏览器流程)。

## 设备归属

每个定义都有归属设备，只有该设备会运行它。从另一台电脑同步来的定义显示“此任务绑定了另一台执行设备”。设备标识保存在 Obsidian 的本机存储中，不要复制本机存储来克隆执行设备。恢复文件不会自动改变运行设备。

## 模块开关

**设置 → 常规 → 功能模块 → 自动化** 控制整个功能，默认开启。关闭时会先等待正在启动的自动化，停止自动化拥有的智能体终端并保存取消状态，然后停止计划检查和文件监听。独立的手动终端不受影响。已经送达的通知和已经完成的文件修改不会被撤销。

关闭期间，自动化页会提示功能已关闭，看板上保存的操作按钮不可用；通知收件箱仍可使用。定义、运行历史和调度游标都保留在磁盘上。重新开启时，会按原有的设备归属、游标和宽限规则检查未处理的触发，不重放已处理的事件。保存开关失败时，开关恢复原值；停止运行或保存运行状态失败时，开关保持新值并提示失败，原因排除后可再次切换。

## 数据保存在哪里

| 内容 | 库内位置 |
|---|---|
| 待办提醒 | 看板笔记，在任务行上 |
| 档案提醒 | 该档案的 `基本信息.md`，位于 `<!-- nand:reminders -->` 标记之间 |
| 倒计时和纪念日 | 看板设置 |
| 独立操作定义 | `NAND/自动化/<名称>-<ID>/操作.md` |
| 调度游标、运行历史 | `.nand/automation/<device-id>/runtime.json` |
| 通知及投递回执 | `.nand/notifications/<device-id>/inbox.json` |
| 自动化启动的会话 | `.nand/terminal-agent/<device-id>/automation-sessions.json` |

请备份相关笔记和整个 `.nand` 目录（见[数据与恢复](data.ZH.md)）。

操作文档无法读取时会报告加载失败，不会当成空操作列表。修复提示中的 Markdown 文件后，可重试加载或重新开启自动化模块。保存和移除定义也会在无法读取最新文档时停止；临时写入失败可在排除原因后重试。

## 使用限制

应用内通知需要 Obsidian 运行，系统通知需要操作系统授权。六种 CLI 智能体的真实账号流程以及移动端尚未全部验证。
