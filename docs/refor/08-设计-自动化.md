# 08 设计：自动化（照搬 Orca Automations）

## 0 定位

- 图标轨「自动化」打开，功能 id `automations`，`chrome: 'none'`，**没有侧栏**（与 Orca 一样全宽）。
- 版式、组件、交互照抄 Orca `src/renderer/src/components/automations/`；去掉 Orca 的“主机/项目/工作区”概念，换成 NAND 的“工作目录（库内文件夹）”。
- 自动化服务 `core/service.ts`、调度解析 `core/schedule/*`（本来就改编自 Orca）、运行存储保持不变；新增字段见 §7。
- 删除动作“浏览器流程”。

## 2 工具栏

| 位置 | 控件 | 说明 |

| 右 | 新建自动化 `Button size="sm"`（`Plus`） | 打开编辑对话框（§4） |

- 点击行（非操作按钮）进入详情（§6）。
- 运行中的自动化行左侧出现 2px `bg-primary` 竖条。
- 删除：`AlertDialog`“删除自动化「周报」？运行记录会保留，可在运行记录页查看。”，可勾选“不再询问”。

├───────────────────────────────────────────────┬──────────────────────────────────────────┤

│ ┌───────────────────────────────────────────┐ │ 智能体     [✱ Claude Code ⌄]              │

- 尺寸：`w-[min(1080px,calc(100vw-2rem))] h-[min(880px,90vh)]`，`p-0 gap-0`，内部 `flex-row`；左栏 `flex-1 min-w-0 p-5`，右栏 `w-[360px] border-l overflow-y-auto p-5 space-y-4`。窄于 760px 时右栏移到下方。
- 打开时焦点在名称（新建）或左侧编辑器（编辑）。Ctrl/Cmd+Enter = 保存。
- 底部：取消（ghost）、保存并运行（outline，仅当有计划或手动动作时）、保存 / 创建（default）。名称或必填项为空时主按钮禁用并在字段下方提示。
- 右栏每个字段用 `Field`（Label + 控件 + 说明），说明 `text-xs text-muted-foreground`。

### 4.2 左栏随动作类型变化

| 动作类型 | 左栏内容 |
|---|---|
| 智能体（默认） | 提示词编辑器（多行，等宽可选），下方“可用变量”芯片（`{{date}}`、`{{time}}`、`{{vault}}`、`{{folder}}`）与“插入笔记引用…”（库内文件选择器，插入 `[[笔记]]` 与绝对路径） |
| 终端脚本 | 代码框（等宽，Tab 缩进）+ 右栏多一个“Shell：PowerShell / Bash” |
| 提醒 | 通知内容（多行） |
| 新建待办 | 看板选择、卡片选择（只列能放待办的卡片）、待办内容 |
| Obsidian 命令 | 命令选择（可搜索的 `Command` 列表） |
| 打开笔记 | 库内文件选择 |
| 打开网址 | 网址输入（在 NAND 浏览器标签打开；浏览器模块关闭时用系统浏览器） |

### 4.3 右栏字段

| 字段 | 控件 | 规则 |
|---|---|---|
| 动作类型 | `Select` | 上表七种 |
| 智能体 | `AgentCombobox`（智能体图标 + 名称，只列已启用的） | 默认 = 默认智能体 |
| 额外参数 | `Input`（等宽） | 只允许模型、推理强度等参数；权限、配置、提示词、会话参数被拒绝（照抄 Orca 的白名单思路）；“沿用会话”时不可用 |
| 工作目录 | 库内文件夹选择（默认库根） | 必须在库内 |
| 会话 | `SegmentedControl`：每次新建 / 沿用上次（上次会话仍存活且空闲时沿用，否则新建）/ 指定会话（展开会话历史选择器） | |
| 频率 | `Select`：仅手动、一次、每小时、每天、工作日、每周、自定义 | 自定义展开 Cron 输入（5 字段）或 RRULE，实时显示“接下来 3 次：…”或错误 |
| 时间 / 星期 / 分钟 | 随频率出现：每小时→分钟（0～59）；每天/工作日→时间；每周→星期 + 时间；一次→日期时间 | |
| 时区 | `Select`（带搜索），默认本机时区 | |
| 补执行宽限 | `Select`：不补执行 / 15 分钟 / 1 小时 / 12 小时（默认）/ 24 小时 | 超出宽限的错过记为“已跳过” |
| 预检命令 | `Input`（等宽，可空） | 定时运行前在工作目录执行；非 0 退出 → 本次“已跳过（预检未通过）”；手动运行也执行，结果显示在运行记录 |
| 通知 | 渠道复选（应用内、系统）+ 时机（成功或失败时 / 仅失败时 / 不通知） | |

## 5 运行记录页（Runs）

工具栏「运行记录」打开，顶部栏变为“自动化 › 运行记录”：

- 表格：开始时间、自动化名称、动作、结果（运行中 / 已提交，完成状态未知 / 成功 / 失败 / 已停止 / 已中断 / 已跳过）、耗时、token（智能体运行前后原生累计值的差，取不到显示“—”）、操作（打开终端、停止、重跑、查看输出）。
- 顶部筛选：结果、自动化、时间范围；“加载更多”分页。
- 点击行打开运行详情（§6.2）。

## 7 数据模型变化

`src/shared/automation/types.ts`：

```ts
export type AutomationAction =
	| { kind: 'agent'; agentId: string; cwd: string; prompt: string; sessionMode: 'fresh' | 'reuse' | 'specific'; session?: AgentSessionRef; extraArgs?: string }   // 新增 extraArgs
	| { kind: 'script'; script: string; cwd: string; shell: 'powershell' | 'bash' }
	| { kind: 'obsidian-command'; command: string }
	| { kind: 'open-file'; path: string }
	| { kind: 'open-url'; url: string }
	| { kind: 'notify'; body: string }
	| { kind: 'create-task'; path: string; cardId: string; text: string };
	// 删除：BrowserWorkflowAction

export interface AutomationDefinition {
	// …原有字段
	precheck?: { command: string; shell: 'powershell' | 'bash' };   // 新增
	templateId?: string;                                           // 新增：由哪个模板创建（仅展示）
}

export interface SourceRef {
	kind: 'dashboard' | 'contacts' | 'widget';                     // 删除 'news' | 'browser' | 'browser-workflow'
	path: string;
	id: string;
}
```

不需要迁移：旧定义文件里出现 `browser-workflow` 动作时，该定义在列表中显示为“不支持的动作（已移除）”，只能删除。

## 8 与其他功能的连接

| 入口 | 行为 |
|---|---|
| 看板待办上的铃铛 | 打开新建对话框，动作=提醒，来源=该待办，名称与时间预填 |

| 通知模块 | 运行结果按定义的通知设置投递（沿用） |
