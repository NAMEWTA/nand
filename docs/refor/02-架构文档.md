## 4 React 在 Obsidian 里的挂载模型

### 4.1 一个页面 = 一个 React 根

Obsidian 的视图和工作台页面都给我们一个 `contentEl`。重构后统一用 `ReactSurface`：

```tsx
// src/ui/react/surface.tsx
import { createRoot, type Root } from 'react-dom/client';
import { NativeSurface, type NativeSurfaceContext } from '../native-surface';
import { NandProviders } from './providers';

/** A NativeSurface whose content is one React tree. Subclasses implement `renderContent()`. */
export abstract class ReactSurface extends NativeSurface {
	private root?: Root;
	private visible = true;

	constructor(context: NativeSurfaceContext) { super(context); }

	protected abstract renderContent(): React.ReactNode;

	override async onOpen(): Promise<void> {
		this.contentEl.addClass('nand-ui');               // 工具类只在 .nand-ui 内生效
		this.root = createRoot(this.contentEl);
		this.rerender();
	}

	protected rerender(): void {
		this.root?.render(
			<NandProviders ownerDocument={this.contentEl.ownerDocument} visible={this.visible}>
				{this.renderContent()}
			</NandProviders>,
		);
	}

	override setVisible(visible: boolean): void {
		super.setVisible(visible);
		this.visible = visible;
		this.rerender();                                   // 组件可据此暂停动画/轮询
	}

	override async onClose(): Promise<void> {
		this.root?.unmount();                              // 一定要卸载，否则监听器泄漏
		this.root = undefined;
	}
}
```

要点：

1. **根容器必须带 `nand-ui` 类**，否则所有 Tailwind 工具类都不生效（见 §5）。
2. **页面隐藏时不卸载**，只是设 `visible=false`。终端、网页切走再切回不能重建。
3. 关闭时 `root.unmount()`。模块停用时外壳会关闭页面，从而卸载。
4. 不在模块顶层捕获 `window`/`document`；需要时用 `useOwnerDocument()`（页面可能在弹出窗口里）。

### 4.3 Portal 根（弹层容器）

Radix 的菜单、弹窗、提示默认渲染到 `document.body`。这有两个问题：① `body` 不在 `.nand-ui` 内，工具类失效；② 弹出窗口里的页面会把弹层画到主窗口。所以：

```ts
// src/ui/react/portal.ts
const roots = new WeakMap<Document, { el: HTMLElement; refs: number }>();

export function acquirePortalRoot(doc: Document): HTMLElement {
	let entry = roots.get(doc);
	if (!entry) {
		const el = doc.body.createDiv({ cls: 'nand-ui nand-portal-root' });
		entry = { el, refs: 0 };
		roots.set(doc, entry);
	}
	entry.refs++;
	return entry.el;
}

export function releasePortalRoot(doc: Document): void {
	const entry = roots.get(doc);
	if (!entry || --entry.refs > 0) return;
	entry.el.remove();
	roots.delete(doc);
}
```

`src/ui/components/` 里每个使用 `*.Portal` 的组件（DropdownMenu、ContextMenu、Popover、HoverCard、Tooltip、Dialog、AlertDialog、Sheet、Select）都改为：

```tsx
const container = usePortalContainer();               // 从 PortalContainerContext 读取
<DropdownMenuPrimitive.Portal container={container}>…</DropdownMenuPrimitive.Portal>
```

`nand-portal-root` 的 CSS 只有一行 `display: contents;`：它不产生盒子、不建立层叠上下文，但 CSS 变量继承和 `.nand-ui` 作用域仍然按 DOM 树生效。每种弹层自己用 Obsidian 的层级变量设 `z-index`：菜单/弹出框 `--layer-menu`（65）、对话框 `--layer-modal`（50）、提示 `--layer-tooltip`（70），见《设计系统》§8。

### 4.4 Obsidian 原生控件还用吗？

| 场景 | 用什么 |
|---|---|
| NAND 界面里的菜单、弹窗、提示、确认框 | Radix（新组件库） |
| 编辑器里的批注浮窗、选区按钮 | Radix Popover，锚定到虚拟矩形（见 §11） |
| 文件/文件夹/命令选择 | Command（cmdk）弹窗；需要模糊搜索整库文件时可用 Obsidian `FuzzySuggestModal`（视觉与 Obsidian 一致，允许） |
| 全局提示（工作台之外，如命令执行结果） | Obsidian `Notice` |
| 渲染 Markdown（备忘卡片、批注正文） | Obsidian `MarkdownRenderer.render`，外层加 `nand-native` 类，让中和层跳过它 |
| 图标 | `lucide-react`；需要显示用户为文件配置的 Obsidian 图标名时用 `setIcon` 包装组件 `<ObsidianIcon name>` |

### 5.3 作用域后处理脚本

```js
// scripts/scope-tailwind.mjs —— PostCSS 插件
// 1) 展开 @layer（分层规则会输给 Obsidian 未分层的 app.css）
// 2) 顶层选择器加作用域并提升特异性：`.x` -> `.x:is(.nand-ui, .nand-ui *):not(#\#)`，特异性 (1,2,0)
// 3) `:root, :host` -> `.nand-ui`
import postcss from 'postcss';

const ROOT = '.nand-ui';
const SCOPE = `:is(${ROOT}, ${ROOT} *):not(#\\#)`;

function scopeSelector(selector) {
	const s = selector.trim();
	if (s === ':root' || s === ':host') return ROOT;
	if (s === '*') return SCOPE;
	if (s.startsWith('::')) return `${SCOPE}${s}`;          // ::before / ::backdrop
	const pe = s.indexOf('::');                               // 伪元素必须在最后
	if (pe > 0) return `${s.slice(0, pe)}${SCOPE}${s.slice(pe)}`;
	return `${s}${SCOPE}`;
}

function hasRuleAncestor(node) {
	for (let p = node.parent; p; p = p.parent) if (p.type === 'rule') return true;
	return false;
}

export const scopeTailwind = () => ({
	postcssPlugin: 'nand-scope-tailwind',
	Once(root) {
		let found = true;
		while (found) {
			found = false;
			root.walkAtRules('layer', (at) => {
				found = true;
				if (at.nodes?.length) at.replaceWith(at.nodes); else at.remove();
			});
		}
		root.walkRules((rule) => {
			if (hasRuleAncestor(rule)) return;                          // 嵌套规则随父级
			if (rule.parent.type === 'atrule' && /keyframes$/.test(rule.parent.name)) return;
			rule.selectors = [...new Set(rule.selectors.map(scopeSelector))];
		});
	},
});
scopeTailwind.postcss = true;
```

```js
// scripts/build-tailwind.mjs
// 用法：
//   node scripts/build-tailwind.mjs                    正式构建 → build/tailwind.scoped.css + 字体 CSS
//   node scripts/build-tailwind.mjs --skip-compile     不重新编译，只对现有 build/tailwind.raw.css 做作用域（dev 用）
//   node scripts/build-tailwind.mjs --write-styles     完成后执行 build-styles.mjs --write（dev 用）
//   node scripts/build-tailwind.mjs --test-hover --out <文件>
//                                                      样式测试构建：hover 不包媒体查询；
//                                                      把“令牌 + 基础 + 中和层 + 工具类”拼成一个文件写到 <文件>
import { execFileSync } from 'node:child_process';
import fs from 'node:fs';
import { createRequire } from 'node:module';
import path from 'node:path';
import postcss from 'postcss';
import { scopeTailwind } from './scope-tailwind.mjs';

const argv = process.argv.slice(2);
const has = (name) => argv.includes(name);
const out = has('--out') ? argv[argv.indexOf('--out') + 1] : null;
const testHover = has('--test-hover');

// 用 node 直接运行 CLI 入口，Windows 上也不需要 .cmd 包装
const require = createRequire(import.meta.url);
const CLI = path.join(path.dirname(require.resolve('@tailwindcss/cli/package.json')), 'dist', 'index.mjs');

fs.mkdirSync('build', { recursive: true });
let entry = 'src/ui/tailwind/index.css';
const RAW = testHover ? 'build/tailwind.test.raw.css' : 'build/tailwind.raw.css';
if (testHover) {
	// 无头 Chrome 里 (hover: hover) 为假，Tailwind 默认的 hover: 规则不会生效。
	// 测试构建用一个入口文件覆盖 hover 变体（@source 仍按 index.css 自己的位置解析）。
	entry = 'build/tailwind.test-entry.css';
	fs.writeFileSync(entry, '@import "../src/ui/tailwind/index.css";\n@custom-variant hover (&:hover);\n');
}
if (!has('--skip-compile')) execFileSync(process.execPath, [CLI, '-i', entry, '-o', RAW, '--optimize'], { stdio: 'inherit' });

const scoped = (await postcss([scopeTailwind()]).process(fs.readFileSync(RAW, 'utf8'), { from: RAW })).css;

if (out) {
	const parts = ['src/ui/styles/tokens.css', 'src/ui/styles/base.css', 'src/ui/styles/neutralize.css'].map((file) => fs.readFileSync(file, 'utf8'));
	fs.writeFileSync(out, [...parts, scoped].join('\n'));
} else {
	fs.writeFileSync('build/tailwind.scoped.css', `/* GENERATED by scripts/build-tailwind.mjs — do not edit */\n${scoped}`);
	writeFontFaces();
	if (has('--write-styles')) execFileSync(process.execPath, ['scripts/build-styles.mjs', '--write'], { stdio: 'inherit' });
}

function writeFontFaces() {
	const faces = [
		['Geist', 'src/ui/fonts/Geist-Variable.woff2'],
		['Geist Mono', 'src/ui/fonts/GeistMono-Variable.woff2'],
	].map(([family, file]) =>
		`@font-face { font-family: "${family}"; src: url(data:font/woff2;base64,${fs.readFileSync(file).toString('base64')}) format("woff2"); font-weight: 100 900; font-style: normal; font-display: swap; }`,
	);
	const next = `/* GENERATED by scripts/build-tailwind.mjs — do not edit. Geist fonts: SIL OFL 1.1 (src/ui/fonts/LICENSE.txt) */\n${faces.join('\n')}\n`;
	const file = 'src/ui/styles/fonts.generated.css';
	// 内容没变就不写，避免 dev 模式下无意义的重建
	if (!fs.existsSync(file) || fs.readFileSync(file, 'utf8') !== next) fs.writeFileSync(file, next);
}
```

`--optimize` 让 Lightning CSS 展开嵌套，产物不依赖 CSS 嵌套语法，对移动端 WebView 更友好；作用域脚本对展开后的复合选择器（如 `.hover\:bg-accent:hover`）同样正确。“测试入口文件覆盖 hover 变体、`@source` 按 `index.css` 自己的位置解析”这两点已用 Tailwind 4.1.13 实测。

规则：

1. **仓库在 `services/` 创建**，跟随模块生命周期（`dispose()` 时停止持久化订阅）。
2. **状态变换写成 `core/` 里的纯函数**，便于单测（沿用现有 `core/terminal/layout.ts` 风格）。
3. **组件只读仓库、调用服务方法**，不直接 `setState`（例外：纯界面临时状态用 `useState`）。
4. **选择器返回稳定引用**：返回数组/对象时用 `useShallow` 或常量空数组，避免无限重绘。
5. 其他模块需要的状态通过 `api.ts` 的服务暴露“只读快照 + subscribe”，不要把仓库对象跨模块传。

智能体工作区只通过 `BROWSER_HOST` 使用浏览器；浏览器模块停用时 `peek` 返回空，「+」菜单隐藏“新建浏览器标签”，已有浏览器标签显示“浏览器模块已关闭”。

**保留层（重要）：** Electron 的 `<webview>` 元素一旦从 DOM 中摘下再插入，就会销毁并重新加载页面（登录态还在，但页面状态、表单、滚动位置丢失）。所以网页**不能**跟着 React 组件在 DOM 树里移动。照抄 Orca（`browser-pane/browser-client-page-retained-elements.ts`）的做法：

1. 每个窗口在 `body` 下建一个保留根 `div[data-nand-browser-retained-root]`（`display: contents`），每个网页一个宿主 `div`（`position: fixed`，默认移到屏幕外 `left: -10000px`），`<webview>` 永远待在自己的宿主里。
2. 浏览器标签的内容区只渲染一个**占位元素**。`mount(placeholder)` 用 `ResizeObserver` + 滚动/窗口尺寸监听，把宿主的 `left/top/width/height` 同步为占位元素的 `getBoundingClientRect()`；`unmount()` 把宿主移回屏幕外。
3. 切换标签、分屏、拖动标签到另一组，都只是换占位元素，网页不重载。
4. 宿主要设置 `z-index` 低于 NAND 弹层（菜单、对话框能盖住网页），并在对话框打开时不需要隐藏网页（Orca 的做法是保留层位于普通内容层级）。
5. 网页移到另一个 Obsidian 窗口时（不同 `document`），只能重建页面——这是 Electron 的限制，NAND 现有行为也是如此。

```
  │                                             （Rust rusqlite，已内置；格式同现有 history 请求，见《实施文档》T5.4）
  │                                             备选 Node `node:sqlite`（process.getBuiltinModule 可用时）
  ├─ decrypt(rows)                            AES-128-CBC（iv=16 个空格，v10/v11）或 AES-256-GCM（Windows，12 字节 nonce + 16 字节 tag）；去掉 32 字节 HMAC/SHA256(host) 前缀
  ├─ filter                                   丢弃 google.com 系、非法域名；统计跳过数
  ├─ replaceImportedDomains(targetSession)    主进程注入代码（host/desktop/electron-main.ts 的 bundledMain）：先删除目标会话中“导入域名”下的旧 Cookie，再逐条 session.cookies.set()，最后 flushStore()
  └─ 结果提示                                 “已从 Chrome（个人资料 1）导入 312 个 Cookie 到 默认；跳过 Google 18 个”
```

时间换算：Chromium 时间戳是从 1601-01-01 起的微秒，`unix = ts/1e6 − 11644473600`。参考实现：Orca `src/main/browser/browser-cookie-*.ts`。

## 14 横切关注点

- **i18n：** 继续用 `t()`；React 组件用 `useT()`（订阅语言变化触发重绘）。新文案写进模块 `i18n.ts`，en/zh 都要有。
- **弹出窗口：** 一律从元素拿 `ownerDocument`；Portal 根按窗口创建；不在模块顶层访问 `window`/`document`。
- **移动端：** 看板、批注面板、设置在移动端可用；智能体工作区在移动端显示“仅桌面可用”空状态；浏览器引擎、Cookie 导入、检测只在 `desktop/` 目录实现。
- **性能：** React、Radix、Tailwind 产物都不进入启动集合；`check:bundle` 的 `forbiddenEagerAreas` 增加 `npm:react-dom`、`npm:radix-ui`。
- **安全：** Cookie 值、OAuth token 不写日志、不进诊断导出；PowerShell/secret-tool 参数通过 stdin 传递，避免注入；webview 保持 `nodeIntegration=false, contextIsolation=true, sandbox=true`。
