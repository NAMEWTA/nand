### T2.2 让 React 与 Preact 暂时并存

现在仓库里有约 186 个文件从 `preact` 导入。我们不一次改完，而是让旧文件继续用 Preact、新文件用 React：

1. 写一个一次性脚本给**所有现有 `.tsx` 文件**加文件级 JSX 来源注释：

   ```js
   // scripts/tmp/add-preact-pragma.mjs（一次性，执行后删除）
   import fs from 'node:fs';
   import { execSync } from 'node:child_process';
   const files = execSync("git ls-files 'src/**/*.tsx'", { encoding: 'utf8' }).trim().split('\n');
   for (const file of files) {
   	const text = fs.readFileSync(file, 'utf8');
   	if (text.startsWith('/** @jsxImportSource preact */')) continue;
   	fs.writeFileSync(file, `/** @jsxImportSource preact */\n${text}`);
   }
   console.log(`pragma added to ${files.length} files`);
   ```

2. `tsconfig.json`：`"jsxImportSource": "react"`。
3. `scripts/esbuild-options.mjs`：删除 `alias` 整行；`jsxImportSource: 'react'`。**不要**给它加 `platform: 'node'`：esbuild 在默认的 `platform: 'browser'` 下会按 `minify` 自动把 `process.env.NODE_ENV` 替换成 `"production"`（正式构建）或 `"development"`（`pnpm dev`），React 靠它选择生产版；改成 node 平台后产物里会留下 `process.env`，Obsidian 移动端没有 `process`，插件会加载失败。
4. `vitest.config.ts`：`importSource: 'react'`；删除两个 `react: 'preact/compat'` 别名；新增 `dom` 项目：

   ```ts
   {
   	...shared,
   	resolve: { alias: { obsidian: repo('./scripts/obsidian-stub.ts') } },
   	test: { name: 'dom', include: ['src/**/*.dom.test.tsx'], environment: 'happy-dom', setupFiles: ['./scripts/module-strings.ts'] },
   },
   ```

5. `pnpm run build`、`pnpm test`：旧代码应照常通过。如果某个测试文件也是 `.tsx` 且用 Preact，同样加注释。
6. 约定：**新文件不加注释**（默认 React）。一个模块迁移完成后，删除它所有旧文件，注释也随之消失。阶段 9 结束时 `grep -rl "@jsxImportSource preact" src` 必须为空，然后 `pnpm remove preact`。

> 两个运行时同时打包会让 `main.js` 变大，这是迁移期的正常现象；预算在阶段 9 收紧。
>
> 这套并存方式已用本仓库的 TypeScript 5.8.3、esbuild 0.25.5、Preact 10.29.8 与 React 19.2.8 / @types/react 19.2.18 实测：带注释的文件按 Preact 做类型检查（可写 `class`）并打包 `preact/jsx-runtime`；不带注释的文件按 React 检查（写 `class` 会报 TS2322，要写 `className`）并打包 `react/jsx-runtime`。

   两个字体约 69 KB 和 71 KB，内联成 base64 后让 `styles.css` 增加约 190 KB（T2.8 调整样式预算）。`build-tailwind.mjs` 末尾生成 `src/ui/styles/fonts.generated.css`（这个生成文件也提交；只有字体变化时内容才会变）：
   ```css
   @font-face { font-family: "Geist"; src: url(data:font/woff2;base64,…) format("woff2");
     font-weight: 100 900; font-style: normal; font-display: swap; }
   ```
4. `src/styles.json` 的 `sources` 最前面加：`src/ui/styles/fonts.generated.css`、`tokens.css`、`base.css`、`neutralize.css`、`build/tailwind.scoped.css`。`.gitignore` 加 `build/`。
5. `package.json`：按《架构文档》§5.3 修改 `build`、新增 `build:css`；`dev` 改为 `node scripts/dev.mjs`：

   ```js
   // scripts/dev.mjs（骨架）：并行运行 esbuild watch 与 tailwind watch，tailwind 产物变化后重跑作用域与拼接
   import { execFileSync, spawn } from 'node:child_process';
   import fs from 'node:fs';
   import { createRequire } from 'node:module';
   import path from 'node:path';
   const require = createRequire(import.meta.url);
   const CLI = path.join(path.dirname(require.resolve('@tailwindcss/cli/package.json')), 'dist', 'index.mjs');
   // 先完整构建一次，保证 build/ 和字体 CSS 都存在
   execFileSync(process.execPath, ['scripts/build-tailwind.mjs', '--write-styles'], { stdio: 'inherit' });
   spawn(process.execPath, ['esbuild.config.mjs'], { stdio: 'inherit' });
   spawn(process.execPath, [CLI, '-i', 'src/ui/tailwind/index.css', '-o', 'build/tailwind.raw.css', '--optimize', '--watch'], { stdio: 'inherit' });
   let timer;
   fs.watch('build', (_, file) => {
   	if (file !== 'tailwind.raw.css') return;
   	clearTimeout(timer);
   	timer = setTimeout(() => spawn(process.execPath, ['scripts/build-tailwind.mjs', '--skip-compile', '--write-styles'], { stdio: 'inherit' }), 150);
   });
   ```

   `build-tailwind.mjs` 的全部参数（`--skip-compile`、`--write-styles`、`--test-hover`、`--out`）见《架构文档》§5.3。所有子进程都用 `process.execPath`（当前 node）直接运行脚本，不用 `node_modules/.bin/…`：CI 也在 Windows 上跑，`.bin` 里是 `.cmd` 包装，`execFileSync`/`spawn` 不能直接执行。
6. `stylelint.config.mjs`（`pnpm run lint:css` 检查 `src/**/*.css`）：
   - 顶层加 `ignoreFiles: ['src/ui/styles/fonts.generated.css']`（`build/` 不在 `src/` 下，本来就不检查）。
   - 在 `overrides` 第一项的 `files` 里加 `src/ui/styles/tokens.css`、`src/modules/home/ui/theme/themes.css`：这两个文件允许字面量颜色（原因写在配置文件的注释里；`scripts/stylelint-baseline.json` 是脚本生成的“文件 → 规则”清单，不写说明）。
   - `z-index` 允许列表加 `'/^var\\(--layer-[a-z-]+\\)$/'`，手写 CSS 才能用 Obsidian 的层级变量（《设计系统》§8）。
   - `src/ui/tailwind/index.css` 里的 `@theme`、`@source`、`@custom-variant` 不会触发现有规则（配置没有启用 `at-rule-no-unknown`）；以后若引入 `stylelint-config-standard`，要把这些 at-rule 加进 `ignoreAtRules`。
7. 因为 `build/tailwind.scoped.css` 不提交，`package.json` 的 `test:styles` 改成 `node scripts/build-tailwind.mjs && node scripts/build-styles.mjs --check`（否则在没构建过的新克隆里会因为找不到文件而失败）。CI 先跑 `pnpm run build` 再 `git diff --exit-code -- main.js styles.css`，所以 Tailwind 产物必须在 Linux 和 Windows 上逐字节一致：锁死 `tailwindcss`/`@tailwindcss/cli` 版本（不用 `^`），构建后在两个平台各跑一次确认。

验证：`pnpm run build:css` 后打开 `styles.css`，能看到 `.inline-flex:is(.nand-ui, .nand-ui *):not(#\#)` 这样的规则，且没有任何 `@layer`。

```ts
// 输入：容器可用宽度、每个片段在详细/精简模式下的测量宽度
// 输出：{ mode, collapsed: providerIds[] }
export function planUsageCollapse(avail: number, items: { id: string; verbose: number; compact: number }[], chipWidth: number) {
	const sum = (ws: number[]) => ws.reduce((a, b) => a + b, 0);
	if (sum(items.map((i) => i.verbose)) <= avail) return { mode: 'verbose', collapsed: [] };
	if (sum(items.map((i) => i.compact)) <= avail) return { mode: 'compact', collapsed: [] };
	const collapsed: string[] = [];
	const visible = [...items];
	while (visible.length && sum(visible.map((i) => i.compact)) + chipWidth > avail) collapsed.unshift(visible.pop()!.id);
	return { mode: 'compact', collapsed };
}
```

     ```jsonc
     { "type": "cookies", "op": "read", "rid": "c-7", "payload": { "path": "/…/tmp/x/Cookies", "kind": "chromium" } }
     // 响应（控制帧）
     { "type": "cookies-result", "rid": "c-7", "data": { "rows": [ { "host_key": ".example.com", "name": "sid", "value": "", "encrypted_value_hex": "763130…", "path": "/", "expires_utc": "13390000000000000", "is_secure": 1, "is_httponly": 1, "samesite": 1 } ] } }
     // 出错
     { "type": "cookies-result", "rid": "c-7", "error": "no such table: cookies" }
     ```
     步骤：在 `Message` 枚举加 `Cookies { op: String, rid: String, #[serde(default)] payload: Value }`；新建 `native/pty-server/src/cookies.rs`（仿照 `data.rs` 在工作线程中处理，用已有的 `rusqlite` 以 `OpenFlags::SQLITE_OPEN_READ_ONLY` 打开，Chromium 执行 `SELECT host_key, name, value, encrypted_value, path, expires_utc, is_secure, is_httponly, samesite FROM cookies`，Firefox 执行 `SELECT host, name, value, path, expiry, isSecure, isHttpOnly, sameSite FROM moz_cookies`；`encrypted_value` 转十六进制字符串——`nand-pty` 没有 base64 依赖，十六进制不用加 crate：`bytes.iter().map(|b| format!("{b:02x}")).collect::<String>()`，TypeScript 侧用 `Buffer.from(hex, 'hex')` 还原；`expires_utc` 是“1601-01-01 起的微秒数”，约 1.3×10¹⁶，超过 JavaScript 的安全整数，Rust 侧按字符串输出（`row.get::<_, i64>(…)?.to_string()`），TypeScript 侧用 `BigInt` 换算成 Unix 秒：`Number(BigInt(s) / 1000000n - 11644473600n)`）；在 `dispatch()` 中加分支。协议版本保持 3（只新增消息类型，不改旧消息）。TypeScript 侧在 `agent/platform/desktop/server/` 仿照 `agent-data-client.ts` 写 `cookie-client.ts`，并通过 `agent/api.ts` 暴露一个只供浏览器模块使用的服务 `NATIVE_HELPER_SQLITE`（浏览器模块不得直接导入 agent 内部）。为 `cookies.rs` 写 Rust 单测（用 rusqlite 现建一个含 `cookies` 表的临时库）。
   - **备选**：`process.getBuiltinModule?.('node:sqlite')` 存在时用 `DatabaseSync` 只读打开。
4. `decrypt.ts`：照抄 Orca `browser-cookie-decryption.ts`（AES-128-CBC v10/v11，AES-256-GCM，去 HMAC/哈希前缀）；`policy.ts`：照抄 `browser-cookie-import-policy.ts` 中的域名规范化与 Google 排除；`validate.ts`：值长度、域名合法性。
5. `write.ts`：通过 `host/desktop/electron-main.ts` 的 `bundledMain` 在主进程执行一段固定代码：对目标会话，先删除“导入域名集合”中的现有 Cookie，再逐条 `cookies.set({ url, name, value, domain, path, secure, httpOnly, expirationDate, sameSite })`，最后 `cookies.flushStore()`；返回成功数与失败数。
6. 文件导入：`file-formats.ts` 解析 Netscape 与 JSON 两种格式（单测各给样本）。
7. 界面：⋯ 菜单子菜单、设置页、toast 文案（《设计-浏览器》§6.2）。
