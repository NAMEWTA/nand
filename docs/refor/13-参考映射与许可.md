加依赖后运行 `pnpm notices`（生成）和 `pnpm check:notices`（校验）。`THIRD-PARTY-NOTICES.md` 是脚本生成的，`check:notices` 会重新生成并逐字比较，**手改一定会失败**。

### 2.1 让 notices 脚本覆盖 `styles.css`

现有 `scripts/third-party-notices.mjs` 只统计两类：esbuild 元数据里打进 `main.js` 的 npm 包、`nand-pty` 链接的 crate。Tailwind、tw-animate-css 和字体只进入 `styles.css`，不会被统计到。在脚本里加一节：

```js
// styles.css 里内嵌的第三方内容：不经过 esbuild，元数据里没有，所以单独列出
const STYLE_PACKAGES = ['tailwindcss', 'tw-animate-css'];
function stylePackages() {
	const packages = STYLE_PACKAGES.map((name) => {
		const dir = path.join(root, 'node_modules', name);
		const manifest = JSON.parse(fs.readFileSync(path.join(dir, 'package.json'), 'utf8'));
		return { name, version: manifest.version, license: manifest.license, dir };
	});
	// 字体放在仓库里（src/ui/fonts/LICENSE.txt 能被 licenseTexts() 识别）
	packages.push({ name: 'Geist and Geist Mono fonts', version: '1.7.2', license: 'OFL-1.1', dir: path.join(root, 'src/ui/fonts') });
	return packages;
}
```

然后在生成正文的数组里、`Bundled in main.js` 一节之后加：

```js
section('Embedded in styles.css', 'CSS and fonts embedded in the plugin stylesheet.', stylePackages(), () => []),
```

并把 `stylePackages()` 的结果也放进脚本已有的“未知/GPL 许可检查”（`unknown` 那一行的数组）。跑 `pnpm notices` 后检查 `THIRD-PARTY-NOTICES.md` 里出现这三项及其许可全文。

## 3 署名怎么写

### 3.1 文件头注释

每个改编自参考项目的源文件，第一行写来源（沿用 NAND 现有惯例，例如 `core/launch/catalog.ts`）：

```ts
// Adapted from stablyai/orca 464bd5a (MIT), Copyright (c) 2026 Lovecast Inc.: src/renderer/src/components/tab-bar/tab-bar-surface.tsx
```

```ts
// Layout and interaction adapted from PandoraReads/apex-dashboard ac4d2c7 (MIT), Copyright (c) 2025 PandoraReads: src/renderer.ts (renderSection)
```

```ts
// Adapted from jonaas-dev/obsidian-margin-comments f727e38 (MIT), Copyright (c) 2026 jonaas-dev: src/anchor.ts
```

CSS 文件同样在开头写 `/* Adapted from … */`。

### 3.2 `NOTICE`

在 `NOTICE` 中：

- 更新 apex-dashboard 段落：新提交号、改编范围（看板布局、主题、交互）。
- 更新 Orca 段落：新提交号、改编范围（工作区、标签、新建菜单、状态栏、用量、浏览器工具栏与 Cookie 导入、自动化页、UI 组件）。

- 新增 shadcn/ui 段落（MIT 全文）。
- 删除 AIHOT、MAIW 段落（对应代码已删除）。

## 4 GPL 与 AGPL 红线

- 根 `AGENTS.md` 规定：**终端代码不复制、不改写 GPL 许可的终端项目**。Orca 是 MIT，可以改编。
- 不要从 GPL/AGPL 项目复制任何东西：包括 Obsidian Copilot（AGPL-3.0）、任何 GPL 的终端项目（如部分 Obsidian 终端插件）、GPL 的 home-pages 类项目。
- 拿不准一个仓库的许可时：看根目录 `LICENSE` 文件（不是 `package.json`），再决定。
- `pnpm run check:similarity`（现有脚本）会扫描与已知 GPL 树的相似度，阶段 10 运行一次。

## 6 照抄时的工作方法

1. 打开参考文件，**先读懂它依赖的状态**（Orca 的组件大多从 `useAppStore` 取数据）。把这些依赖替换成 NAND 的服务/仓库，列一张“Orca 字段 → NAND 来源”的对照（写在 PR 描述或提交说明里）。
2. **保留 Tailwind 类名原样**，这是照抄的核心价值。删掉 NAND 没有的功能分支（SSH、远程主机、移动端、worktree、遥测、引导教程）。
3. 文案：Orca 用 `translate('key', 'English')`；NAND 用 `t('模块.键')`，在模块 `i18n.ts` 里写 en（照抄 Orca 英文）和 zh（自己翻译，遵守《设计系统》§12 文案规则）。
4. 写完后与参考截图/本机 Orca 对照。
