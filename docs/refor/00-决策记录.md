## D01 总体策略：保留骨架，重做界面与交互，不保兼容

**背景。** NAND 现有的模块系统、懒加载、`.nand/` 数据根、i18n、原生终端辅助程序 `nand-pty` 都经过了大量验收；问题集中在界面和交互上：看板不像 apex、终端不像 Orca、组件丑、风格不统一。用户明确说“无需考虑兼容性”。

**决定。**

- 保留：插件 id、`src/app/main.ts` 入口、`ModuleRegistry` 模块系统、`manifest.ts / api.ts / module.ts` 三件套、分区导入矩阵、`.nand/` 数据根、`t()` 词典、`nand-pty` 原生辅助程序（协议 3）、终端核心（xterm 封装、帧协议、Shell 集成）、各模块的 `core/` 纯逻辑。
- 重做：所有 `ui/` 目录、`src/shell/`、`src/ui/`、设置页、样式体系。
- 不保兼容：设置命名空间、看板文件格式、评论旁路文件格式、工作台叶子状态都可以改，**不写迁移代码**。旧数据文件留在磁盘上不删除，新版本读不懂就忽略。

**理由。** 重写骨架风险高、收益低；界面层是用户不满意的全部来源。

**放弃的方案。** ① 推倒重来新建插件——违反仓库规则“不新建脚手架、不改插件 id”。② 只换皮不换交互——不能满足“照搬 apex/Orca 交互”。

**影响。** 代码量最大的是 `modules/home/ui`（约 3.8 万行）和 `modules/agent/ui`。`core/` 和 `platform/` 的大部分逻辑可复用。

## D02 UI 技术栈：React 19 + shadcn/ui + Tailwind CSS v4

**背景。** 用户要求“使用成熟的 UI 组件库，做到整体设计风格统一、组件统一、字体统一，参考最成熟热门并且在 Obsidian 插件里有使用的”。当前 NAND 用 Preact + 自研原语，规则里禁止 shadcn、Tailwind。

**调研结论。**

| 候选 | 在 Obsidian 插件中的使用 | 与参考项目的关系 |
|---|---|---|
| **shadcn/ui（Radix + Tailwind）** | Obsidian Copilot（下载量最大的 AI 插件之一）用 React 18 + Tailwind 3（前缀 `tw-`、关闭 preflight）+ shadcn new-york + Radix + lucide-react | **Orca 本身就是 React 19 + Tailwind v4 + shadcn new-york-v4 + Radix + lucide-react**，组件可直接照搬 |
| 纯 Radix + 手写 CSS | Smart Composer 用 React 18 + Radix + lucide-react + 普通 CSS | 需要自己写全部样式，统一难度大 |
| Svelte 系（obsidian-svelte 等） | Tasks、Projects、Omnisearch 等用 Svelte | 与 Orca/apex 都不一致，需要换框架 |
| MUI / Ant Design / Chakra | 极少用于 Obsidian 插件，体积大、风格强，难以跟随 Obsidian 主题 | 无 |

**决定。** 采用 **shadcn/ui（new-york-v4 风格）**，具体依赖：

- `react`、`react-dom`（19.2 系列，与 Orca 相同）
- `radix-ui`（统一包）、`class-variance-authority`、`clsx`、`tailwind-merge`
- `tailwindcss`、`@tailwindcss/cli`（4.1 系列）、`tw-animate-css`
- `lucide-react`（与 Obsidian 内置图标同为 Lucide）
- `cmdk`（命令面板、「+」新建菜单的搜索框）、`sonner`（轻提示）
- `zustand`（状态）、`@dnd-kit/core` + `@dnd-kit/sortable`（拖拽）、`@tanstack/react-virtual`（长列表）、`react-resizable-panels`（分屏）

组件源码按 shadcn 的方式**复制进仓库** `src/ui/components/`，以 Orca 的 `src/renderer/src/components/ui/` 为蓝本修改。

**理由。** ① 用户要求照搬 Orca，同栈才能“照抄”而不是“仿写”；② Obsidian Copilot 证明这套栈在 Obsidian 里可行（注意：Copilot 是 **AGPL-3.0**，只借鉴做法，**不得复制其任何代码**；组件代码一律取自 MIT 的 Orca 与 shadcn/ui）；③ Radix 自带键盘与读屏支持，省掉 NAND 现有大量手写可访问性代码；④ 组件源码在仓库里，可以随意改。

**放弃的方案。** 继续用 Preact + `preact/compat` 跑 Radix——Radix 依赖 React 的一些行为（`useId`、事件系统、`flushSync`），compat 层在边缘情况下会出问题，排查成本高，而 Obsidian 插件对包体并不敏感（`main.js` 现在已有 4.6 MB）。

**影响。** 全部 `.tsx` 改为 React；`esbuild` 去掉 `preact/compat` 别名；`tsconfig` 的 `jsxImportSource` 改为 `react`；包体预算上调（理由记录在 `scripts/bundle-budget.json`）。

## D03 CSS 隔离：去分层 + `.nand-ui` 作用域 + ID 级特异性 + 中和层

**背景。** Obsidian 的 `app.css` 没有使用 `@layer`，并且对 `button`、`input`、`select`、`textarea` 有全局样式，其中输入框悬停规则特异性高达 (0,3,1)。Tailwind v4 把工具类放在 `@layer utilities` 里，而**任何分层样式在层叠中都输给未分层样式**，所以直接引入 Tailwind，工具类会被 Obsidian 覆盖。另外 NAND 的样式不能泄漏到 Obsidian 其他界面。

**决定。** 构建时对 Tailwind 输出做后处理（脚本见《架构文档》§5）：

1. 展开所有 `@layer` 块，变成普通规则；
2. 每条顶层选择器改写为 `原选择器:is(.nand-ui, .nand-ui *):not(#\#)`，特异性升到 (1,2,0)，只在 `.nand-ui` 内生效；
3. `:root, :host` 改写为 `.nand-ui`（主题变量挂在 NAND 根上）；
4. 另写一份「中和层」CSS，把 Obsidian 对表单元素的默认样式在 `.nand-ui` 内清零，特异性 (1,0,1)，低于工具类、高于任何 Obsidian 或社区主题的类选择器（含 `:hover` 等状态规则，所以不需要单独的悬停中和规则）；Obsidian 原生内容（`.markdown-rendered`、`.nand-native`、`.cm-editor`）不中和；
5. 设计令牌从 Obsidian 变量派生，自动跟随亮/暗色和社区主题；
6. 所有 Radix 弹层（Portal）渲染到每个窗口 `body` 下的 `div.nand-ui.nand-portal-root`。

**验证。** 已在 Obsidian 1.13.7 提取出的真实 `app.css` 上，用无头 Chrome 153 + DevTools 协议实测 shadcn 的 Button（default/ghost/outline）、Input、Textarea 在亮/暗主题下的常态、悬停、聚焦计算样式，全部正确；未加工具类的原生按钮被完全清零；`.markdown-rendered` 内的按钮/输入框和带 `.nand-native` 的复选框与 NAND 外部的同类元素计算样式完全一致（2026-10-14 复测）。

**放弃的方案。** ① Tailwind 类名前缀（Copilot 的做法）：照抄 Orca 时要改写每个类名，容易错；② Shadow DOM：Radix 的“点击外部关闭”在 Shadow DOM 里会误判，xterm 与 CodeMirror 也有焦点问题；③ 全局 `!important`：会压过 JS 写入的行内样式。

**影响。** 新增 `scripts/build-tailwind.mjs`；`styles.css` 由“Tailwind 产物 + 作者 CSS”拼接；stylelint 跳过生成文件。

**决定。** 界面字体统一为 `Geist`（随插件打包，SIL OFL 1.1），中文回退到系统字体：

## D08 浏览器：并入智能体工作区，删除扩展功能

**背景。** 用户要求“浏览器属于终端 Agent，与 Orca 同一逻辑，新建标签可以是 CLI 也可以是网址；学习 Orca 的浏览器管理控制，可选默认搜索引擎、会话和 Cookie 导入；不需要本地浏览器外接”。经询问，用户选择**删除** AI 工作台、受限网页助手和浏览器流程。

**决定。**

- 浏览器页面成为智能体工作区里的一种标签，不再有独立的图标轨入口和独立侧栏。
- `browser` 模块保留，但只做“浏览器引擎”：网页宿主（`<webview>`）、Profile 与会话目录、Cookie 导入、下载、查找、缩放、视口、开发者工具、元素抓取、截图标注、站点权限。它通过 `api.ts` 暴露 `BROWSER_HOST` 服务，智能体工作区用它创建和渲染浏览器标签。
- 新增：默认搜索引擎（Google / Bing / 百度 / DuckDuckGo / 自定义模板）、默认主页、默认缩放、Profile 管理、从 Chrome/Edge/Brave/Arc/Firefox 和 Cookie 文件导入、链接路由（终端/笔记中的链接在 NAND 浏览器或系统浏览器打开）。

## D10 批注：右侧栏常驻视图 + 行级批注 + 悬停弹窗

**决定。** 参考 Margin Comments（MIT）：

- 「批注」视图在布局就绪时用 `workspace.ensureSideLeaf()` 放进**右侧栏**，图标常驻（`message-square-text`），点击即看当前笔记的批注；面板可切换“当前笔记 / 全库”、“全部 / 未解决 / 已解决”、排序。

- 锚点：保存被批注文字的原文、前后 50 字上下文、行号提示；重定位依次用精确匹配 → 上下文 → 模糊匹配（有界编辑距离，阈值 0.3）。

## D16 明确不做的 Orca 功能

| 功能 | 不做的理由 |
|---|---|
| Git worktree、项目/仓库管理、分支 | NAND 以库（vault）为工作目录，不管理代码仓库 |
| SSH、远程 Orca 服务器、WSL 主机切换 | 用户明确不需要 |
| 移动伴侣 App、云 VM | 与 Obsidian 插件形态无关 |
| GitHub/GitLab/Linear/Jira、PR 审阅、diff 批注 | 不是 NAND 的核心能力 |
| Monaco 编辑器、文件树、Markdown 编辑标签 | Obsidian 本身就是编辑器 |
| Orca CLI、浏览器 CLI 控制 | 与“删除本地外接”一致 |
| Computer Use、语音听写、插件市场、Artifacts、宠物 | 非核心 |
| 浮动终端 | 可作为后续增强，本次不做 |
