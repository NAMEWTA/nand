# NAND 全面重构文档（refor）

这套文档描述 NAND 插件的一次**不考虑兼容性**的全面重构：首页看板照搬 apex-dashboard，智能体/终端/浏览器/自动化/用量照搬 Orca，批注改成“右侧栏图标 + 悬停查看编辑”，删除新闻模块和浏览器扩展功能，并换成一套成熟、统一的 UI 组件库。

文档面向**第一次接触这个仓库的实现者**。只要按「阅读顺序」读完、再按《实施文档》一步步做，就能完成重构。遇到术语看本页末尾的「术语表」，遇到坑看《常见问题与排错》。

> 文档写于 2026-10-13～14，基于仓库提交 `63cfd94`、NAND 0.0.2-alpha.1。参考项目版本见《参考映射与许可》。
>
> **哪些内容已经实测过（2026-10-14，Linux）：** ① 样式隔离方案：从《架构文档》§5 原样抽出 `scope-tailwind.mjs`、`build-tailwind.mjs`、Tailwind 入口和中和层，加上《测试与验收》§3.2 的验证脚本、样例与期望值，在 Obsidian 1.13.7 的真实 `app.css` + Chrome 153 上端到端运行通过（亮/暗），并确认故意改坏中和层时脚本会报错；② React 与 Preact 按文件并存（《实施文档》T2.2），用本仓库的 TypeScript 与 esbuild 版本做了类型检查和打包；③ Geist 字体的获取命令。其余部分（Orca/apex 复刻、Cookie 导入、批注等）是设计与实施说明，尚未写成代码。

## 阅读顺序

1. **第一天：建立全局认识。** 读本页 → 《决策记录》 → 《需求文档》的第 1～4 章。
2. **第二天：理解要怎么搭。** 读《架构文档》和《设计系统》。不用记住每个令牌，知道“去哪里查”即可。
3. **开工前：只读你负责的那份设计文档**（04～09 之一），再读《实施文档》里对应的阶段。
4. **做的时候：** 对照《参考映射与许可》打开上游源码照抄，对照《测试与验收》自测。卡住了查《常见问题与排错》。

## 范围一览

**做：**

- 设计系统：React 19 + shadcn/ui + Tailwind v4 + Radix + lucide-react，含与 Obsidian 样式隔离的构建方案（已在 Obsidian 1.13.7 的真实 `app.css` 上用无头 Chrome 验证）。
- 工作台外壳：图标轨、侧栏、页面外框全部用新组件重写；新增 Orca 式底部状态栏。
- 首页看板：apex-dashboard 复刻（三种布局、横幅、侧栏小组件、常用操作条、分区与卡片、13 款主题、外观工作室、统计弹窗）。
- 智能体工作区：Orca 式布局、标签与分屏、「+」新建菜单（含网址/搜索）、智能体状态、会话历史、智能体看板、快捷命令、重启后恢复。
- 用量：状态栏用量条、用量面板、账号切换、用量统计页。
- 智能体管理：已安装检测、启用/停用、默认智能体、命令/参数/环境覆盖、权限模式、状态 Hook、账号。
- 浏览器：Orca 式标签与工具栏、默认搜索引擎、主页、默认缩放、Profile、Cookie 导入、下载栏、查找、视口、开发者工具、元素抓取与截图标注、链接路由、站点权限。
- 自动化：Orca 式列表、筛选、编辑对话框、调度选择器、运行记录。
- 批注：右侧栏批注视图、行级/选区批注、悬停弹窗、模糊重锚。
- 删除：新闻模块；浏览器 AI 工作台、受限网页助手、浏览器流程、本地外接（限定授权与会话级 CLI 桥）。
- 设置页、档案、图标、Git 同步、通知等其余页面统一换成新组件（排在后面的阶段）。

**不做：** worktree、SSH、远程主机、移动伴侣 App、GitHub/Linear/Jira、内置代码编辑器与 diff 审阅、Computer Use、语音、插件市场、Artifacts、Orca CLI。完整理由见《决策记录》D16。

## 关键约束（来自仓库规则，重构后仍然有效）

- 插件 id 仍是 `nand`，入口仍是 `src/app/main.ts`，产物仍是提交到仓库的 `main.js` 和 `styles.css`。
- 全部 NAND 管理的数据仍在当前库的 `.nand/` 下，受管 Markdown 在 `.nand/content/`。
- 模块化、懒加载、模块之间只通过对方的 `api.ts` 访问——这些架构规则保留。
- 面向用户的文案一律走 `t()`，并在模块词典里同时写 `en` 和 `zh`。
- 终端相关代码不得复制或改写 GPL 许可的终端项目；Orca、apex-dashboard、Margin Comments、shadcn/ui 都是 MIT，可以改编但必须署名。
- 用户没要求时不提交、不推送、不发版。

> **注意：** 仓库当前的界面规则（`.agents/skills/ui/references/design-system.md`）明确**禁止** shadcn、Tailwind 和 dnd-kit。重构第一步就是按《实施文档》阶段 0 修改这些规则文件，否则规则和实现会互相矛盾。

## 术语表

| 术语 | 含义 |
|---|---|
| 工作台（workbench） | NAND 注册的唯一主视图 `nand-workbench-view`，所有页面都在里面 |
| 图标轨（rail） | 工作台最左侧 52px 的图标栏，每个功能一个图标 |
| 侧栏（side panel） | 图标轨右侧的第 2 栏，显示当前功能的对象列表 |
| 页面（page） | 第 3 栏的主要内容区 |
| 页面外框（chrome） | 页面上方 44px 的页头。重构后页面可以选择不要页头，自己画顶部栏 |
| 状态栏（status bar） | 重构新增的工作台底部 24px 横条，照抄 Orca，显示用量和运行状态 |
| 智能体工作区 | 图标轨上「智能体」打开的页面，照抄 Orca 的主界面；内部功能 id 仍叫 `terminal` |
| 标签（tab） | 智能体工作区顶部标签条里的一项，可以是终端、智能体终端或浏览器页面 |
| 标签组（tab group） | 一列标签加它们共享的内容区。分屏就是多个标签组并排 |
| 会话（session） | 一个运行中的终端进程（普通 Shell 或智能体 CLI） |
| 智能体（agent） | Claude Code、Codex、Gemini CLI 等编程智能体命令行工具 |
| 用量（usage） | 智能体订阅额度的使用比例（5 小时窗口、每周窗口等），以及 token 用量 |
| Profile | 浏览器的独立身份：自己的 Cookie、缓存、登录状态 |
| 看板（board / dashboard） | 首页显示的一份 Markdown 文件，apex 中叫“工作台”（workspace） |
| 分区（section） | 看板里的一个横向区块，如「便利贴」「数据库」 |
| 小组件（widget） | 看板侧栏里的卡片，如天气、番茄钟 |
| 批注（comment / annotation） | 挂在笔记某段文字或某一行上的讨论线程，不改动笔记正文 |
| 令牌（token） | 设计系统里的 CSS 变量，如 `--background`、`--primary` |
| `.nand-ui` | 所有 NAND React 界面的根容器类名，Tailwind 工具类只在它里面生效 |
| shadcn/ui | 一套“复制到自己仓库里用”的 React 组件源码，底层是 Radix 和 Tailwind |
| Radix | 无样式、可访问的 React 交互组件库（菜单、弹窗、提示等），shadcn 的底座 |
| Tailwind | 原子化 CSS 框架，用 `flex`、`px-3` 这类类名写样式 |
| Orca | stablyai/orca，并行运行编程智能体的桌面 IDE，本次重构的主要参考 |
| apex | PandoraReads/apex-dashboard，Obsidian 看板插件，首页的参考 |
| Margin Comments | jonaas-dev/obsidian-margin-comments，批注的主要参考 |
