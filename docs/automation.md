# 自动化与通知

从功能区的计时器图标、命令面板“自动化”或设置中的“自动化”打开管理中心。铃铛打开持久化通知收件箱。

## 创建与运行

- **待办提醒**：在看板待办的提醒按钮中选择时间、通知渠道。任务仍属于原看板笔记；勾选完成或删除后不再调度。
- **档案提醒**：在档案记录菜单选择“新建自动化”，填写内容和时间。管理中心的“来源”打开档案面板并选中记录。
- **自动创建待办**：新建自动化，动作选择“新建待办”，选择目标看板及卡片，再输入待办内容。可以马上创建，或按周期创建。
- **Agent 自动化**：选择已启用的 Coding Agent，输入提示词和本机工作目录，再选择运行方式。不设定时间时，保存为手动快捷操作；在管理中心点击“立即运行”。

通知渠道可多选。应用内通知写入收件箱并显示 Obsidian 提示；系统通知使用桌面系统通知权限。邮件、短信保留渠道标识和禁用入口，尚未连接服务商。选择“成功或失败时”“仅失败时”或“不通知”控制任务结果通知。

Agent 支持每次新建、复用上次仍存活且空闲的会话、指定原生历史会话。历史选择器支持搜索；也可填写准确的会话标识，Pi 还需要会话文件路径。指定会话走原生恢复参数，不回退到新会话。复用模式在上次终端已退出时新建。

手动运行自动打开终端；定时运行可从历史记录点击“打开”。终端菜单的“收起面板”保留进程；关闭工作台标签只隐藏界面，重新打开可接回存活进程；点击会话的关闭按钮或运行记录中的“停止”才结束进程。关闭自动化中心不停止调度。

## 首页开关

首页的“自动化”开关控制定时与手动运行，旧设置缺少此开关时默认开启。关闭后会等待正在启动的自动化，并停止自动化拥有的智能体终端、保存取消状态；独立手动终端不受影响。已经送达的通知和已经完成的文件修改不会撤销。

关闭期间仍可查看定义和运行历史、打开来源及使用通知中心（包括标记已读）；新建、编辑、删除、运行和清理运行历史不可用。定义、游标和通知回执继续保留，重启后仍保持关闭。重新开启按原有设备归属、调度游标和宽限规则检查未处理的触发，不重放已处理事件。

设置保存失败会恢复开关；若停止任务或保存运行状态失败，会提示切换失败并保持执行关闭。修复故障后再次切换会先完成停止，再允许新运行。

## 时间与恢复

- Obsidian 必须运行。没有云端调度、操作系统守护进程、远程运行或 worktree 创建。
- 支持马上执行、一次执行、每小时／每天／工作日／每周，以及五字段 cron。RRULE 支持 `FREQ=HOURLY|DAILY|WEEKLY` 与 `BYHOUR/BYMINUTE`，每周支持 `BYDAY`；不支持的字段会拒绝保存，不会默默忽略。
- 时间按执行设备当前时区解释，每分钟检查一次，窗口获得焦点时再次检查。
- 错过时间只考虑最近一次，不补排所有历史执行；默认宽限 720 分钟，加两分钟轮询容差。超时或上一轮尚未结束会记录“跳过”。
- 先保存待执行记录和调度游标，再执行动作。插件重启将未完成记录标为“中断”，不会自动重放。任务创建还带有运行标识，以免同一运行重复插入。
- 每个定义保留最近 100 条已结束记录，活动记录始终保留。通知以运行 ID 去重；重启后无法确认投递结果的渠道保留“状态未知”，不自动重发。

旧 `⏰` 待办提醒会写入稳定标识、设备归属和自动化元数据。倒计时和纪念日沿用原配置入口，由插件级服务执行；其中日期由小组件配置决定。无需保持看板打开。

## Agent 能力边界

对外支持 Claude Code、Codex、Gemini、OpenCode、Pi 和 Grok。Pi 指 `@mariozechner/pi-coding-agent`，Grok 指 `xai-org/grok-build`。历史只显示当前库及其子目录中的会话，参见[工作台说明](agent-workbench.md)。

Claude Code、Codex、Gemini 合并原生 hook，保留用户设置与其他 hook，并备份原文件。Grok 使用独立的 `hooks/nand-status.json`；Pi 安装原生扩展，OpenCode 安装原生插件。托管文件在 NAND 启动环境以外不发送事件。Pi 等待真正 idle/settled，OpenCode 忽略子会话和可恢复错误；不把静默时长当作完成。

CLI 自身的工作目录信任、登录和 hook 权限仍由 CLI 管理，需要先手动完成。对没有原生完成事件的 CLI，运行显示“完成状态未知”，直至真实进程退出或用户停止；不使用输出静默推断成功。输入式 CLI 必须发出可识别的输入就绪信号，否则超时失败，提示手动完成初始化。

## 数据与备份

| 内容 | 库内位置 |
|---|---|
| 看板待办及提醒 | 原看板笔记 |
| 档案提醒 | 原档案笔记 |
| 倒计时和纪念日 | NAND 的小组件设置 |
| 独立定义、调度进度、运行历史 | `.nand/automation/<device-id>.json` |
| 通知及投递回执 | `.nand/notifications/` |
| 自动化终端会话关联 | `.nand/automation-sessions/` |

执行设备标识保存在 Obsidian 本机存储中。同步笔记中的提醒只由绑定设备执行；独立定义和运行历史按设备分文件保存。不要复制本机存储来克隆执行设备。备份时保留相关笔记、插件设置和 `.nand` 数据目录；恢复文件不会把运行设备自动改成另一台机器。

删除定义会保留运行快照，列表中仍可查看其历史；清理已结束历史不会删除活动运行。收件箱支持全部已读、清理已读及来源跳转，清理后仍保留防止重复投递的依据。

## 使用限制

应用内通知需要 Obsidian 运行，系统通知需要操作系统授权。各 CLI 的登录、目录信任和 hook 权限需要先手动完成；六种 CLI 的真实账号流程以及移动端尚未全部验证。

自动化用量取原生会话累计值在运行前后的差额；取不到基线或原生记录时显示缺失，不推算费用。
