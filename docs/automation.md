# 自动化与通知

从功能区的计时器图标、命令面板“自动化”或设置中的“自动化”打开管理中心。铃铛打开持久化通知收件箱。

## 创建与运行

- **待办提醒**：在看板待办的提醒按钮中选择时间、通知渠道。任务仍属于原看板笔记；勾选完成或删除后不再调度。
- **档案提醒**：在档案记录菜单选择“新建自动化”，填写内容和时间。管理中心的“来源”返回原笔记。
- **自动创建待办**：新建自动化，动作选择“新建待办”，选择目标看板及卡片，再输入待办内容。可以马上创建，或按周期创建。
- **Agent 自动化**：选择已启用的 Coding Agent，输入提示词和本机工作目录，再选择运行方式。不设定时间时，保存为手动快捷操作；在管理中心点击“立即运行”。

通知渠道可多选。应用内通知写入收件箱并显示 Obsidian 提示；系统通知使用桌面系统通知权限。邮件、短信保留渠道标识和禁用入口，尚未连接服务商。选择“成功或失败时”“仅失败时”或“不通知”控制任务结果通知。

Agent 支持每次新建、复用上次仍存活且空闲的会话、指定原生历史会话。历史选择器支持搜索；也可填写准确的会话标识，Pi/Prime Agent 还需要会话文件路径。指定会话走原生恢复参数，不回退到新会话。复用模式在上次终端已退出时新建。

手动运行自动打开终端；定时运行可从历史记录点击“打开”。终端菜单的“收起面板”保留进程；关闭终端标签或在运行记录中点击“停止”会结束进程。关闭自动化中心不停止调度。

## 时间与恢复

- Obsidian 必须运行。没有云端调度、操作系统守护进程、远程运行或 worktree 创建。
- 支持马上执行、一次执行、每小时／每天／工作日／每周，以及五字段 cron。RRULE 支持 `FREQ=HOURLY|DAILY|WEEKLY` 与 `BYHOUR/BYMINUTE`，每周支持 `BYDAY`；不支持的字段会拒绝保存，不会默默忽略。
- 时间按执行设备当前时区解释，每分钟检查一次，窗口获得焦点时再次检查。
- 错过时间只考虑最近一次，不补排所有历史执行；默认宽限 720 分钟，加两分钟轮询容差。超时或上一轮尚未结束会记录“跳过”。
- 先保存待执行记录和调度游标，再执行动作。插件重启将未完成记录标为“中断”，不会自动重放。任务创建还带有运行标识，以免同一运行重复插入。
- 每个定义保留最近 100 条已结束记录，活动记录始终保留。通知以运行 ID 去重；重启后无法确认投递结果的渠道保留“状态未知”，不自动重发。

旧 `⏰` 待办提醒会写入稳定标识、设备归属和自动化元数据。倒计时和纪念日沿用原配置入口，由插件级服务执行；其中日期由小组件配置决定。无需保持看板打开。

## Agent 能力边界

启动参数参考 [Orca 的固定版本](https://github.com/stablyai/orca/tree/27b823f934f739bc85914dd717b776835f60bcf7)，包含 38 个独立 CLI 定义，并保留 NAND 原有 MiniMax。Orca 的 `claude-agent-teams` 依赖其运行时，本版不迁入。

17 类原生恢复参数：Claude Code、Codex、Gemini、Antigravity、OpenCode、OpenCode2、Pi、MiMo Code、Droid、Grok、Devin、OMP、Prime Agent、Copilot、Kimi、Muse、Zcode。这表示具备恢复参数适配，不表示所有 CLI 版本均已实机验证。

自动发现覆盖 Claude/Codex/Gemini、Pi 系列、Droid、Copilot、Grok、Devin、Muse、Kimi 和 OpenCode 旧文件布局，并合并 NAND 自己捕获的会话。新版 SQLite 布局、没有工作目录的历史或其它 CLI 可用“会话标识”入口；不会根据不确定的目录猜测会话归属。

Claude Code、Codex、Gemini、Droid 接入原生开始／结束 hook。首次自动化启动时合并对应用户配置，保留其它设置与 hook，原文件备份到 `.nand-backup`。托管脚本位于用户目录 `.nand/hooks/nand-automation-hook.cjs`；没有 NAND 传入的临时事件目录与令牌时立即退出。配置文件格式错误或并发修改会阻止覆盖。

CLI 自身的工作目录信任、登录和 hook 权限仍由 CLI 管理，需要先手动完成。对没有原生完成事件的 CLI，运行显示“完成状态未知”，直至真实进程退出或用户停止；不使用输出静默推断成功。输入式 CLI 必须发出可识别的输入就绪信号，否则超时失败，提示手动完成初始化。新版 Rust 服务报告真实退出码；旧服务的固定退出码不会被视为成功依据。

## 数据与实现位置

| 内容 | 位置 |
|---|---|
| 调度、历史、编辑器和自动化视图 | `src/automation/` |
| 通知渠道、投递记录和收件箱 | `src/notifications/` |
| 公共数据结构、接口、任务元数据 | `src/shared/automation/` |
| 产品组合与注入 | `src/plugin/automation-host.ts` |
| 原生终端运行和 hook 适配 | `src/terminal-agent/launch/automation-*` |
| 看板待办定义 | 原任务行的 `nand-task` HTML 注释 |
| 档案提醒定义 | 原笔记的 `nand:reminders` 区域 |
| 独立定义、游标、运行快照 | `.nand/automation/<device-id>.json` |
| 通知记录、会话索引 | `.nand/notifications/`、`.nand/automation-sessions/` |

执行设备标识保存在 Obsidian 本机存储中。同步笔记中的提醒只由绑定设备执行；独立定义和运行历史按设备分文件保存。不要复制本机存储来克隆执行设备。JSON 存储串行写临时文件再替换，保留上次有效快照；损坏主文件恢复前另存 `.corrupt`。

## 验证与交付

`pnpm run test:automation` 验证调度、恢复、通知去重、元数据和 hook 合并；`test:terminal-agent`、`test:settings-nav`、`test:contacts` 和相关看板回归覆盖现有功能。`node scripts/verify-pty-automation.mjs` 对本机 Rust 服务验证输出、快速退出、非零退出码及关闭进程树。

本次没有 Obsidian 桌面／移动端真机 UI 验证，也没有安装并实跑全部 39 个 CLI。系统通知权限、各 CLI 原生 hook 版本兼容、浮动窗口和真实登录流程仍需在目标设备验收。

发布工作流从同一个提交构建五个平台的 Rust 服务及校验和，不再上传旧的仓库二进制。本地验证为 Linux x64；其它平台由 CI 构建，尚未在本工作区执行。上游许可见 [Orca MIT 许可](third-party/orca-LICENSE.txt)，完整文本也进入 `main.js` 的构建声明。
