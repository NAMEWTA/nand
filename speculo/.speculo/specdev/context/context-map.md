# NAND Context Map

本图描述领域协作与数据归属，不把源码五层当成业务领域，也不将同进程协作描述成分布式服务。

| 上下文 | 协作对象 | 已确认关系 |
|---|---|---|
| 插件壳层 | 所有产品领域 | 组合设置、注册入口、按模块生命周期装配宿主能力；不接管领域正文数据 |
| 看板 | 自动化 | 看板拥有待办和部件来源定义，自动化通过来源端口读取和请求更新 |
| 档案 | 自动化 | 档案拥有记录及提醒正文区域，自动化按来源请求读写和跳转 |
| 自动化 | 终端与编程智能体 | 自动化通过运行端口启动、停止或打开会话；终端负责原生进程和状态 |
| 自动化 | 通知 | 运行结果产生通知请求；通知投递不决定 Agent 原生执行是否成功 |
| 通知 | 看板、档案、自动化 | 通过组合根注入的导航操作跳转来源或运行，不直接接管其 UI |
| 终端与编程智能体 | CLI 原生历史 | CLI 拥有原始记录及恢复协议，NAND 只读并保存自己的索引、标注和导出 |
| 编辑器评论 | Obsidian 笔记 | 评论通过原文锚点关联，独立持久化；正文仍由笔记拥有 |
| 图标 | Obsidian 原生界面 | 使用独立图标数据装饰界面；既不拥有笔记正文，也不替换看板图标系统 |

跨领域协调归插件壳层的组合操作。看板、档案、评论和图标各自保留资料所有权，不能因为界面同处一个工作台就合并持久化。
