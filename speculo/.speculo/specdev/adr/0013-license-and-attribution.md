# ADR-0013: MIT license and third-party attribution

Status: accepted. Checked against the code on 2026-10-08.

## Problem

NAND adapts designs and code from other projects, bundles npm packages into `main.js` and links Rust crates into the terminal helper. To be distributable under one permissive license, everything that ships must be compatible with it, and every source must be credited where the license requires it. This is engineering practice, not legal advice.

## Decision

- **NAND is MIT.** `LICENSE` holds the text. Everything that ships in `main.js`, `styles.css` or the helper must be compatible with MIT distribution.
- **Where attribution lives.**
  - `NOTICE` lists the works NAND adapts, with their license texts: apex-dashboard and obsidian-dashboard (MIT, the board design), Orca (MIT, with the pinned commit mapping), Iconic (MIT-0, with its resource licenses), obsidian-git (MIT, the behavior of git sync), and a statement that the terminal and its helper are written for NAND.
  - `THIRD-PARTY-NOTICES.md` is generated by `scripts/third-party-notices.mjs`. It lists every npm package bundled into `main.js` and every crate linked into `nand-pty`, with license texts. The generator refuses unknown and GPL licenses, and `pnpm run check:notices` fails when the file does not match the bundle and the crate graph.
  - `src/modules/icons/core/res/NOTICE.txt` credits icon resources and Unicode data.
  - `docs/third-party/` records what is adapted from Orca and holds its license text.
  - The `main.js` banner embeds `LICENSE`, `NOTICE`, the icon resource notices, the Orca license and the licenses of bundled packages. Release assets attach `LICENSE`, `NOTICE` and `THIRD-PARTY-NOTICES.md`.
- **Dependencies.** MIT, ISC, BSD, Apache-2.0, MIT-0, CC0, Unicode and Zlib are accepted. GPL, AGPL, LGPL for bundled code, SSPL and unlicensed code are not. A new dependency is loaded lazily where possible and followed by regenerating `THIRD-PARTY-NOTICES.md`; Rust builds use `--locked`.
- **Adapted code.** Code from an MIT, ISC or BSD project may be adapted if the file names its source and upstream commit in a header comment, `NOTICE` has the entry with the upstream's own copyright lines, and the file mapping is recorded. GPL projects are studied only for public behavior and user-visible concepts; their source is not opened while writing NAND code and is not paraphrased.
- **The terminal.** The terminal (`src/modules/agent`) and `native/pty-server` contain no GPL code. They are built from public behavior and documentation: Orca (MIT), xterm.js and its add-ons, `portable-pty`, and public protocol specifications (xterm control sequences, the kitty keyboard protocol, win32-input-mode, ConPTY, VS Code shell integration sequences, OSC 7).
- **Similarity gate.** `scripts/check-similarity.mjs` compares token k-grams of NAND's tree with reference trees and prints only paths and numbers. A file whose raw share with a reference file reaches 0.15, or that has a raw run longer than 40 tokens, is investigated; the top normalized matches are reviewed by hand. It runs after large terminal changes and before a release, with reference trees kept outside the repository.

## Consequences

Adding a dependency or adapting code has a fixed checklist, and the notice files are checked mechanically where they can be. Similarity checks need reference trees that are not in the repository.
