# ADR-0014：统一工作台入口

状态：已接受，当前规范。核对日期：2026-10-05。

## 问题

看板、档案、自动化、通知、浏览器和智能体各自占用功能区入口。设置里的“首页”又和日常打开的看板共用一个名字。若页面显隐会启动终端，或关闭一个网页就关掉整个工作台，导航就和业务生命周期绑在一起。

## 决策

日常入口只有功能区的“打开工作台”。工作台内的“首页”是看板，技术功能 ID 仍是 `dashboard`。设置产品 ID `home`（设置 → NAND → 首页）只放通用设置和模块开关，不是工作台首页。

工作台用页面槽切换共享呈现层，不嵌套 ItemView，也不另做一套终端路由器。切换会话、历史或用量不新建标签，也不隐式启动 PTY。关闭一个浏览器页面不关闭工作台。只有显式的“在原生标签页中打开”和“在分屏中打开”才离开当前页槽。六个既有视图类型保留，供独立标签和恢复使用。工作台外壳的视图类型记在开发技能的身份表中。

底部状态只投影需要处理或正在运行的项。桌面用状态栏；手机把同一组状态放进页头。用量只有一个数据源。习惯和记账仍是看板小组件，不进入工作台导航。

根 `styles.css` 仍是唯一分发样式。作者源若按显式顺序拼回这份文件，选择器顺序必须与拆分前一致。

## 取舍与约束

不把旧视图类型改名，不用新类型给旧叶子做版本。模块开关仍是服务闸门，不是关标签。导航不创建会话。关闭工作台叶子只释放呈现，不终止已有 PTY。领域独立增强（习惯、记账等独立页面）本轮不做。不改插件版本，不因此关闭既有 Issue。
