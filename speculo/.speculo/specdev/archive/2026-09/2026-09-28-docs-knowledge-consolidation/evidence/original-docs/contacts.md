# 档案面板使用指南

档案是 NAND 的独立功能面板，与看板平级。日常通过联系人卡片、企业卡片和详情页查看、编辑资料；Markdown 文件负责保存资料，方便备份、直接阅读和提供给 AI。

## 开始使用

1. 在 **设置 → NAND → 首页** 确认“档案”已开启。
2. 进入 **设置 → NAND → 档案**，选择或输入资料文件夹，点击 **预览并应用**。确认框会显示目标目录及识别到的档案数量。
3. 点击功能区的通讯录图标，或执行命令 **NAND：打开档案**。
4. 在 **联系人** 页点击 **新增**，填写姓名和联系方式并保存。点击卡片进入详情页，继续添加履历、关系及备注。
5. 在 **企业** 页建档，记录企业的特别情况；也可以在新增工作经历时，通过企业选择器创建企业。

每个编辑窗口都有明确的保存操作。未保存的草稿尚未写入 Markdown，不能依靠重启插件恢复。创建企业是单独的保存操作，随后取消工作经历不会删除已经创建的企业。

## 设置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 档案模块开关 | 开启 | 在 NAND 首页切换。关闭模块保留资料文件 |
| 档案资料文件夹 | `档案` | 当前 Obsidian 库内的可见目录；可输入尚不存在的目录，首次保存档案时创建 |
| 卡片最大列数 | 6 | 可选 5 或 6；窗口变窄时自动减少，不保证固定列数 |

路径示例：`资料/档案`。不支持库外绝对路径、隐藏目录或 `..` 上级路径。修改目录文本后，必须经过“预览并应用”才会切换；切换不会搬移或删除旧目录中的文件。

## 人物与企业

| 资料 | 填写方式与用途 |
| --- | --- |
| 姓名、别名 | 姓名必填。同名人物可以分别建档，系统用独立身份标识区分 |
| 手机、固定电话、微信、邮箱 | 支持多项，每行一项；电话按文本保存，保留前导零和国际区号 |
| 出生日期、出生地 | 日期使用 `YYYY-MM-DD`，不知道时可留空 |
| 当前地区、标签 | 用于查找和筛选。人物当前地区与企业地区分别填写，不自动互相覆盖 |
| 工作经历 | 企业、部门、职务、起止日期、现任／曾任、关键角色及任职备注 |
| 人际关系 | 关联另一位联系人，选择关系，可补充关联企业和备注 |
| 性格与偏好、生活习惯、备注 | 支持普通文字和 Markdown，保存后在详情页中预览 |
| 企业资料 | 名称、联系方式、网址、地区、标签及企业特别情况；人员列表来自人物的工作经历 |

### 记录履历

在人物详情的 **工作经历** 中添加任职。日期可用 `YYYY-MM` 或 `YYYY-MM-DD`，也可以留空。状态以明确选择的“现任／曾任”为准：离职后设为“曾任”，即使结束时间不清楚也可以保留；“现任”不能填写结束日期。同一个人可以同时在多家企业任职。

将现任经历的 **关键角色** 设为“负责人”或“关键联系人”，该人物就会出现在企业详情的 **关键人物** 中。这是任职角色，与两个人之间的“领导／下属”关系分别记录。

企业详情列出当前任职和曾任职人员。人数表示**已收录的在职联系人**，不能用来表示企业实际员工总数；同一人物在同一企业有多段职务时，人数仍只计一次。

### 记录人际关系

关系字段的含义是“**对方是此人的……**”。例如，在张三的档案里选择李四，关系选“领导”，表示李四是张三的领导；李四的详情会反向显示张三是其下属。

领导／下属互为反向，同事／朋友双向展示。只需录入一次，反向展示来自原始关系，不会另写一份记录。来自对方档案的关系应回到记录来源修改。自定义关系会显示来源及原始称谓，不自动推断另一种称谓。

同属一家企业只构成任职关联，不自动生成朋友或同事关系。尚未建档的人物需要先创建联系人，再添加直接关系。

## 查找和浏览

| 方式 | 范围 |
| --- | --- |
| 搜索 | 基本资料、联系方式、任职企业名称和职务；备注及自由正文不在此搜索范围内 |
| 联系人筛选 | 当前公司、曾任公司、当前地区、标签、关系类型 |
| 企业筛选 | 企业地区、标签 |
| 排序 | 按姓名／名称，或最近修改 |

同一筛选项内多选表示“或”，不同筛选项之间表示“且”。例如，当前公司选择 A 和 B，地区选择杭州，结果是“在 A 或 B 任职，并且人物当前地区为杭州”的联系人。

卡片列表和企业人员列表每页最多 60 条。点击企业或人物链接可在档案内继续浏览，返回时恢复列表位置。手机上的新增、筛选、排序及删除入口在标签页菜单，各详情分区保留编辑按钮。**打开原始笔记** 是需要检查底层文件时的辅助入口。

## 文件、备份与停用

每个人、每家企业分别保存为可见的 Markdown 文件。默认布局如下；同名文件会增加身份标识后缀：

```text
档案/
  联系人/张三.md
  企业/星河科技.md
  档案格式说明.md
```

基本字段保存在 YAML 属性中，履历和关系保存在正文表格中，性格、习惯和备注保存在正文区域。HTML 注释标记记录身份与编辑边界，实际资料仍是普通 Markdown。详细规则见 [文件格式说明](../src/contacts/persist/format-guide.md)。

面板从文件建立内存索引，联系人资料不依赖插件目录中的数据库或 `data.json`。插件设置只保留所选目录、显示偏好等配置。首次创建档案时，若目录内没有 `档案格式说明.md`，会同时生成一份说明；已有说明不会在升级时被覆盖。

### 备份和迁移

1. 完成并保存面板或原始笔记中的编辑。
2. 复制整个资料目录，保留子目录结构。若正文引用了目录外的图片或附件，还应一并备份这些文件。
3. 在另一库中放入该目录，通过设置选择它；档案内容和关联索引会从文件重建。目录偏好和面板布局不随资料目录备份。

在当前库移动目录时，同样先完成编辑，整体移动后重新选择目录。切换到空目录时面板显示为空，旧资料仍在原位置；切回旧目录即可继续读取。

关闭模块或卸载 NAND 保留已保存的 Markdown。此后可以通过 Obsidian、文本编辑器或 AI 直接读取；重新启用 NAND 并选择资料目录即可恢复面板。这个机制保证资料不依赖面板存在，磁盘损坏或误删仍需要独立备份处理。

### 删除和恢复

删除人物或企业会按 Obsidian 的删除设置处理文件，不级联删除其他档案。其他人的历史履历、关系文字与引用会保留，无法找到的目标显示为失效关联。

需要恢复时，从所用回收站或备份恢复原文件，保留原来的 `nand-id`；不要仅创建一个同名的新档案代替，因为新档案有不同身份。

## 外部编辑与问题处理

原始笔记保存后的变化会触发面板刷新。面板保存时比较打开表单时的内容与当前文件：不同基本字段或不同正文区域的修改可合并，同一字段或同一张履历／关系表的并发修改会报告冲突，不按行自动合并。

| 提示或现象 | 处理方式 |
| --- | --- |
| 相同字段已被修改 | 当前表单保留草稿。先点“复制草稿”留存，再“重新载入原始资料”，检查最新内容后重新编辑。复制结果是 JSON 文本，用于找回输入，不是 Markdown 导出或可直接导入的文件 |
| 原始笔记有未保存编辑 | 先在原始笔记中完成保存，再回到面板处理草稿 |
| 资料文件夹已切换 | 先复制需要保留的草稿，再从当前目录重新打开档案；旧表单不能写入新目录 |
| 属性、表格或区域标记无效 | 打开原始笔记，对照格式说明修正；面板会阻止覆盖损坏内容 |
| 多份文件使用同一个 ID | 检查是否复制了原文件；若要创建另一个人，优先通过面板新增，不要复制身份标识 |
| 可见链接与关联身份不一致 | 对照原始笔记核对链接目标及身份注释，不要只改其中一项 |
| 部分档案读取失败 | 检查相关文件是否可读，再点“重新读取”；其他正常档案仍可显示 |
| 档案已保存，但格式说明未能创建 | 该档案已写入；检查目录写入状态。之后创建档案时会再次尝试生成缺失说明 |

草稿只在当前编辑窗口中保留，关掉窗口或重启前请完成保存或复制。面板的冲突检查也不能替代同步工具对跨设备文件冲突的处理。

## 让 AI 阅读

把资料目录和其中的 `档案格式说明.md` 提供给 AI 即可，无需面板接口。例如：“读取这份档案目录，列出星河科技已收录的现任联系人及职务，附上来源文件；区分现任和曾任，不推测未记录的关系。”

文件中的相对链接可用于追踪人物与企业，`nand-id` 可用于区分同名记录。是否把文件发送到外部 AI 服务由使用者选择，档案面板本身不提供自动 AI 上传或同步功能。

## 当前范围

已实现手工建档、面板编辑、企业视角、任职履历、直接人际关系、组合筛选与 Markdown 持久化。CSV／Excel 导入、手机通讯录同步、关系网络图、生日提醒和跨设备冲突协调尚未包含。

实现位置、回归检查与实际 Obsidian 验收项目见 [开发说明](contacts-development.md)。
