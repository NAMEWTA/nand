# Spec: 开发文档知识沉淀

## 1. 问题与目标
docs 混有用户指南、开发设计和历史验收。外部用户需要纯使用说明，维护者需要可追溯且经代码验证的长期知识。

## 2. 解决方案与外部行为
44 份材料完整快照；提炼九份 ADR、八个领域词汇表和 Context Map；公开目录只保留四份用户指南、工作台配图和许可证。开发证据随本次 change 归档。
失败时保留已完成副本和处理清单；源或目标漂移时停止相关清理，不覆盖既有归档。

## 3. 用户故事
- US-001：作为用户，我只需阅读操作、备份和能力限制。
- US-002：作为维护者，我能找到当前决策、规范术语及未失真的历史依据。

## 5. 范围
### IN
文档分类、知识毕业、快照、用户指南改稿、引用与领域布局规则更新、归档。
### REUSE
SpecDev A 网关、既有状态 schema、dev 和 skill-creator 的窄范围维护规则。
### OUT
产品实现、数据迁移、远程 Issue 操作、提交、发布、第三方 API 重新研究、GUI 复验。

## 6. 已锁定实现约束
- DEC-001：用户文档留在 <Path>docs/</Path>，维护知识位于 <Path>{roots.state}/specdev/</Path>。
- DEC-002：原始材料不改写；领域术语不容纳代码导航和测试流水账。
- DEC-003：通过当前代码与既有测试核验现有设计，不为凑 ADR 编造历史动机。

## 7. 数据、接口与兼容
公共 API、类型和产品存储格式无变化。文档路径发生变化，现役入口统一更新；原许可证继续供构建读取。

## 8. 非功能要求
原件保真和可恢复；保护工作区及既有归档。性能与产品监控不适用：未改变运行行为。

## 9. 验证策略
一次性文档检查覆盖 KC-001 至 KC-006。运行 SpecDev 自检、归档前 complete、归档后默认校验与状态检查，以及架构、build、lint。历史产品测试结果仅作为带版本的原始证据；本次不重复宣称 GUI 验收。

## 10. 风险、假设与未决问题
### 风险
早期材料有旧标识、失效源码链接、不同测试数量和测试环境绕过；原件保留，派生知识以当前代码为准。
### 已采用的低影响假设
中文工件；本次为非产品实现型知识整理，不建立实现 Ticket、空提交或虚构集成 SHA。KC 表示知识整理的等价验收合同，ready_for_tickets=false 表示不进入拆票阶段，不表示知识未获批准。来源为本地用户请求，无远程 reconcile 或 publish 任务。
### 未决问题
无。
