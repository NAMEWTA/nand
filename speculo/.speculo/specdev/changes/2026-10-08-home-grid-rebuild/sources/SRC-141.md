**严重程度 / Severity**：S3（一般）｜**建议优先级 / Priority**：P3｜**复现率 / Frequency**：3/3（640 宽窗口，中 / 英界面；从其他页面回首页后仍如此）｜**类型**：缺陷（布局）

## 问题概述 / Summary
桌面窗口宽度 ≤ 640px 时，工作台「首页」横幅下面的快捷创建栏（`.dashboard-quicknote`）被**拉伸到约 1950px 高**。

首屏横幅下面只剩一个空的浅紫色大框，「还没有快捷创建按钮 / 添加按钮」被挤到框的竖直中间（约第 1150px），周历、最近编辑和看板分区都在约 2165px 以下。用户看到的像是首页加载失败。

窗口 ≥ 660px 时一切正常（栏高 71px）。

## 复现步骤 / Steps to reproduce
1. 把 Obsidian 窗口调到 640×740（左侧文件栏展开，工作台窗格约 288px 宽）
2. 打开工作台 →「首页」

## 期望结果 / Expected behavior
快捷创建栏保持一行高度，下面紧接周历、最近编辑和看板（与 660px 以上一致）。

## 实际结果 / Actual behavior
- 横幅下只有一个空的大框（截图红框），要滚动约两屏才能看到任何内容
- `.dashboard-main` 是 `flex-direction: column`，`.dashboard-quicknote` 的 `flex` 是 `0 0 100%`，高 1951px，`scrollHeight` 3839
- 不同窗口宽度下快捷栏的高度：640 → **1951px**；660 / 680 / 700 / 800 / 900 / 1000 → 71px

![home-640](https://gist.githubusercontent.com/NAMEWTA/055537ff620ae786bd57e0033896754f/raw/nand-r24-16-home-quicknote-640.png)

## 原因（推断）
`src/modules/home/styles/021-stacked-layout-desktop-tablet-only.css` 里把快捷栏改成 `flex: 0 0 auto` 的覆盖规则写在 `@media (min-width: 641px)` 内。注释也说明：基础样式 `flex-basis: 100%` 在列布局里会变成**高度**。

视口 ≤ 640px 时这条覆盖不生效，但工作台首页的 `.dashboard-main` 仍然是列布局，于是 `flex-basis: 100%` 把快捷栏撑到容器全高。按注释，这个区间本该由手机样式接管，但桌面窗口（`isStackedLayout` 仍是 stacked）落在了两套规则的空档里。

## 附带观察
同一宽度下，横幅左上角的计数徽标「1」和「+」按钮压在名言第一行文字上（截图左上），影响较小，供参考。
